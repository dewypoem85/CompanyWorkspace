# Sheet 개발 명세

> 상태: 설계 초안 0.3  
> 최종 수정: 2026-08-25  
> 대상: Google Sheets 기반 게임 데이터·번역 관리 도구

## 1. 제품 정의

Sheet는 회사 Google Workspace에 저장된 데이터 스프레드시트와 번역 스프레드시트의 기존 공동 편집 방식을 유지하면서, 두 문서 사이의 한국어 원문 갱신, 번역 상태 추적, 스냅샷, 개발·라이브 릴리스를 관리하는 사내 웹 애플리케이션이다.

Sheet는 Google Sheets를 대체하는 편집기가 아니다. 사용자는 기존처럼 Google Sheets에서 스프레드시트와 탭을 만들고 삭제하며 데이터를 편집한다. Sheet는 관리 대상으로 등록된 문서를 Google Drive API와 Google Sheets API로 읽고, 검증된 갱신 작업만 번역 스프레드시트에 반영한다.

핵심 기능은 다음 네 가지다.

1. 기존 `IMPORTRANGE` 수식을 일반 값으로 마이그레이션한다.
2. 데이터 스프레드시트의 한국어 원문을 번역 스프레드시트의 `Korean` 열로 갱신한다.
3. 한국어 원문 변경에 따라 다른 언어의 재번역 상태를 관리한다.
4. 변경 불가능한 스냅샷과 개발·라이브 릴리스를 관리한다.

## 2. 배경과 해결하려는 문제

현재 데이터 스프레드시트와 번역 스프레드시트는 `IMPORTRANGE` 수식으로 연결되어 있다. 이 구조에는 다음 문제가 있다.

- 다수의 외부 참조 수식이 Google Sheets 내부 계산 부하를 증가시킨다.
- Unity에서 번역 스프레드시트를 불러올 때 수식 결과가 기대한 시점에 갱신되지 않을 수 있다.
- 데이터 스프레드시트와 번역 스프레드시트의 연결 관계가 개별 셀 수식에 분산되어 관리하기 어렵다.
- 데이터 원문이 변경되어도 다른 언어 번역의 재검토 필요 여부를 체계적으로 확인하기 어렵다.
- 여러 사람이 원본 문서를 계속 수정하므로 개발 중 데이터가 라이브 데이터에 섞일 수 있다.
- 데이터는 변경되었지만 관련 번역을 갱신하지 않은 상태로 배포할 수 있다.
- 문제가 발생했을 때 배포 당시의 정확한 문서 상태를 재현하거나 되돌리기 어렵다.

Sheet는 번역 스프레드시트에서 외부 참조 수식을 제거하고 일반 값만 유지한다. 끊어진 데이터 연결은 웹 애플리케이션의 명시적인 갱신 규칙과 실행 이력으로 대체한다.

## 3. 현재 문서 기준 현황

2026-08-24에 확인한 `I2Loc 던전슬래셔 번역` 스프레드시트의 현황이다. 실제 수치는 이후 공동 편집에 따라 달라질 수 있다.

- 번역 탭: `Common`, `Default`, `인앱결제`, `Mission`, `Tutorial`, `Cartoon`, `SinStat`, `Trait`, `Pass`
- 기본 열: `Keys`, `Korean`, `English`, `Japanese`, `Chinese`, `Chinese (Taiwan)`, `Spain`
- `IMPORTRANGE` 수식: 총 3,710개
- 모든 `IMPORTRANGE`는 다른 수식으로 감싸지 않은 단독 수식이다.
- 모든 참조는 범위가 아닌 단일 셀 참조다.
- 참조하는 원본 Spreadsheet는 4개다.
- 주요 분포: `Default` 3,142개, `Trait` 535개, `SinStat` 33개

대표 연결은 다음과 같다.

```text
원본
PlayerInfoTable / #소환술사!D33
값: 이상한 던전의 소환술사

대상
I2Loc 던전슬래셔 번역 / Default!B1578
키: SummonerSkinName2
열: Korean
```

## 4. 용어

| 용어 | 정의 |
|---|---|
| Spreadsheet | Google Drive에 저장되는 하나의 Google Sheets 문서 파일 |
| Sheet 또는 탭 | Spreadsheet 내부의 개별 워크시트 탭 |
| 데이터 스프레드시트 | 게임 데이터와 한국어 원문의 기준이 되는 Spreadsheet |
| 번역 스프레드시트 | Unity에서 사용하는 키와 언어별 번역 값을 가진 Spreadsheet |
| 갱신 규칙 | 원본 위치와 번역 대상 위치의 연결 관계 및 변환 정책 |
| 갱신 작업 | 갱신 규칙을 실행해 변경 예정 값을 계산하고 반영하는 한 번의 실행 |
| 스냅샷 | 특정 시점의 관리 대상 데이터를 변경 불가능하게 보관한 사본 |
| 릴리스 | 서로 정합성이 확인된 하나 이상의 스냅샷 묶음 |
| 개발 채널 | 개발 및 테스트에서 사용할 현재 릴리스를 가리키는 채널 |
| 라이브 채널 | 라이브 서비스에서 사용할 승인된 현재 릴리스를 가리키는 채널 |

## 5. 제품 원칙

- Google Sheets가 공동 편집의 원본 시스템이다.
- Sheet 웹사이트에서는 범용 스프레드시트 편집 기능을 구현하지 않는다.
- 번역 스프레드시트에는 `IMPORTRANGE`가 아닌 일반 값만 저장한다.
- 데이터 스프레드시트에서 자동 갱신하는 언어는 한국어뿐이다.
- 한국어 이외의 언어 값은 자동 덮어쓰기하지 않는다.
- 모든 쓰기 작업은 실행 전 변경 미리보기와 스냅샷을 거친다.
- 모든 갱신과 배포는 사용자, 시각, 입력 버전, 결과 버전을 추적할 수 있어야 한다.
- 라이브는 공동 편집 중인 원본을 직접 참조하지 않고 승인된 릴리스를 사용한다.

## 6. 사용자와 권한

### 6.1 역할

| 역할 | 주요 권한 |
|---|---|
| 조회자 | 등록 문서, 변경 비교, 스냅샷 및 릴리스 조회 |
| 작업자 | 갱신 미리보기, 데이터→번역 갱신, 번역 상태 변경 |
| 승인자 | 개발 릴리스 생성, 라이브 승격, 롤백 |
| 관리자 | 관리 문서 등록, 갱신 규칙 관리, 사용자·권한 관리 |

한 사용자가 여러 역할을 가질 수 있다. 라이브 승격 권한은 일반 갱신 권한과 분리한다.

### 6.2 인증

- 회사 Google Workspace 계정으로 로그인한다.
- 허용된 회사 도메인의 사용자만 접근할 수 있다.
- Google Spreadsheet 접근 권한과 Sheet 내부 역할을 모두 검사한다.
- 백그라운드 작업용 서비스 계정을 사용할 경우 명시적으로 공유된 Spreadsheet에만 접근하게 한다.

## 7. 기능 요구사항

### 7.1 기능 1 — `IMPORTRANGE` 마이그레이션

#### 수식 탐색

- 관리 대상 번역 Spreadsheet의 모든 탭에서 `IMPORTRANGE` 수식을 탐색한다.
- 대상 Spreadsheet, 대상 탭, 대상 셀, 대상 키, 대상 언어를 기록한다.
- 수식에서 원본 Spreadsheet ID, 원본 탭, 원본 A1 주소를 추출한다.
- 단독 `IMPORTRANGE`, 결합 수식, 범위 참조를 구분하고 지원하지 않는 형태를 보고한다.
- 수식 오류인 셀은 일반 오류 문자열로 변환하지 않고 마이그레이션을 차단한다.

#### 갱신 규칙 생성

- 탐색된 수식 하나마다 초기 셀 기반 갱신 규칙을 생성한다.
- 동일한 원본·대상 패턴은 묶어서 조회하고 실행할 수 있어야 한다.
- 원본 행에 안정적인 키가 존재하면 셀 주소 규칙을 키 조회 규칙으로 전환할 수 있어야 한다.
- 규칙에는 생성 근거가 된 원본 수식과 생성 시각을 보관한다.

#### 일반 값 변환

- 변환 전 번역 Spreadsheet 전체의 스냅샷을 생성한다.
- 각 `IMPORTRANGE`의 현재 정상 계산 결과를 읽는다.
- 같은 셀에 Google Sheets API의 `RAW` 입력 방식으로 일반 값을 기록한다.
- 셀의 기존 서식, 메모, 유효성 검사는 보존한다.
- `IMPORTRANGE`가 아닌 다른 수식은 변경하지 않는다.
- 변환 후 대상 값이 변환 전 표시 값과 동일한지 검증한다.
- 변환 후 남아 있는 `IMPORTRANGE` 수식 수를 보고한다.
- 일부 셀만 실패하면 전체 작업을 성공으로 표시하지 않으며 복구 절차를 제공한다.

#### 마이그레이션 완료 조건

- 현재 기준 3,710개 수식이 모두 갱신 규칙으로 등록된다.
- 정상 수식은 동일한 일반 값으로 변환된다.
- 번역 Spreadsheet에 `IMPORTRANGE` 수식이 0개다.
- 변환 전 스냅샷으로 복구할 수 있다.

### 7.2 기능 2 — 데이터 시트의 한국어 값을 번역 시트로 갱신

#### 갱신 대상

- 데이터 Spreadsheet를 원본, 번역 Spreadsheet를 대상으로 등록한다.
- 번역 대상 탭의 기본 구조는 `Keys` 열과 언어별 열이다.
- 기본 한국어 대상 열은 `Korean`이며 탭별로 설정을 재정의할 수 있다.
- 영어, 일본어, 중국어 간체·번체, 스페인어 등 다른 언어는 자동 변경하지 않는다.

#### 갱신 규칙 종류

초기 버전은 다음 두 종류를 지원한다.

1. 셀 규칙: 지정한 원본 셀의 값을 지정한 번역 키와 한국어 열로 복사한다.
2. 키 규칙: 원본 탭에서 안정적인 행 키를 찾고 지정한 원문 열의 값을 번역 키와 한국어 열로 복사한다.

기존 수식 호환을 위해 셀 규칙을 먼저 제공하되, 행 추가·삭제에 안전한 키 규칙을 권장한다.

```ts
interface SyncRule {
  id: string;
  enabled: boolean;
  source: {
    spreadsheetId: string;
    sheetId: number;
    sheetTitle: string;
    selector:
      | { type: 'cell'; address: string }
      | { type: 'key'; keyColumn: string; keyValue: string; valueColumn: string };
  };
  target: {
    spreadsheetId: string;
    sheetId: number;
    sheetTitle: string;
    translationKey: string;
    languageColumn: 'Korean';
  };
}
```

#### 갱신 실행

- 사용자는 데이터 Spreadsheet 또는 등록된 규칙 집합을 선택해 갱신을 시작한다.
- 시스템은 원본과 현재 번역 한국어 값을 읽고 변경 예정 목록을 계산한다.
- 변경 없음, 추가, 수정, 삭제 후보, 충돌로 구분한다.
- 변경 전후 값과 원본·대상 위치를 미리보기로 표시한다.
- 사용자는 전체 또는 선택 항목만 반영할 수 있다.
- 반영 직전 원본이 미리보기 생성 시점 이후 변경되지 않았는지 재검증한다.
- 반영 전 대상 Spreadsheet 스냅샷을 생성한다.
- 값은 수식이 아닌 `RAW` 일반 값으로 일괄 기록한다.
- 대상 한국어 열 이외의 언어 열은 변경하지 않는다.
- 갱신 작업 단위로 실행 결과와 실패 항목을 기록한다.

#### 추가·수정·삭제 정책

- 원본 항목 추가: 번역 키와 Korean 값을 추가하고 다른 언어는 빈 값으로 둔다.
- 원문 수정: Korean 값을 갱신하고 다른 언어를 재번역 필요 상태로 전환한다.
- 원본 항목 삭제: 기본 동작은 즉시 삭제가 아니라 삭제 후보 표시다.
- 번역 키 변경: 기본적으로 기존 키 삭제 후보와 신규 키 추가로 처리한다.
- 대상 Korean 값이 규칙 외부에서 수정된 경우 덮어쓰기 전 충돌로 표시한다.
- 빈 원문, 중복 키, 원본 키 누락, 대상 키 중복은 반영 전에 오류로 처리한다.

### 7.3 기능 3 — 재번역 상태 관리

#### 상태 단위

재번역 상태는 번역 Spreadsheet에 새로운 상태 열을 강제로 추가하지 않고 Sheet 서버 데이터베이스에서 `번역 키 × 언어` 단위로 관리한다.

| 상태 | 의미 |
|---|---|
| 최신 | 현재 한국어 원문을 기준으로 번역 검토가 완료됨 |
| 재번역 필요 | 한국어 원문이 변경된 후 해당 언어가 아직 검토되지 않음 |
| 번역 없음 | 해당 언어 셀이 비어 있음 |
| 변경 감지 | 재번역 필요 이후 언어 셀의 값 변경이 감지됨 |
| 제외 | 해당 키 또는 언어는 번역 대상이 아님 |
| 삭제 후보 | 원본에서 사라졌으나 번역 시트에는 남아 있음 |
| 충돌 | 원본·대상 또는 여러 규칙 사이의 자동 판단이 불가능함 |

#### 상태 전환

- Korean 원문이 변경되면 대상 언어를 `재번역 필요`로 전환한다.
- Korean 값만 갱신하고 기존 번역 값은 보존한다.
- 재번역 필요 이후 다른 언어 셀의 값이 바뀌면 `변경 감지`로 전환한다.
- 작업자 또는 승인자가 검토 완료 처리하면 `최신`으로 전환한다.
- 원문이 변경되지 않은 항목의 번역 상태는 유지한다.
- 상태 변경 시 사용자, 시각, 기준 한국어 값의 해시를 기록한다.

#### 조회와 배포 검사

- Spreadsheet, 탭, 번역 키, 언어, 상태로 필터링할 수 있다.
- 재번역 필요 및 번역 없음 건수를 언어별로 표시한다.
- 항목에서 원본 셀과 번역 셀의 Google Sheets 링크를 열 수 있다.
- 라이브 릴리스 전 재번역 미완료 항목을 검사한다.
- 차단 오류와 승인 가능한 경고의 기준을 관리할 수 있어야 한다.

### 7.4 기능 4 — 스냅샷과 개발·라이브 릴리스

#### 스냅샷

- 최초 마이그레이션, 갱신 반영, 릴리스 생성 전에 스냅샷을 생성한다.
- 스냅샷은 생성 후 수정할 수 없다.
- Spreadsheet ID, 탭별 값, 수식, 문서 메타데이터, 생성자, 생성 시각, 데이터 해시를 보관한다.
- 스냅샷이 기준으로 삼은 Google Drive 문서 버전과 마지막 수정 시각을 기록한다.
- 현재 문서와 임의의 스냅샷을 키 및 셀 단위로 비교할 수 있다.
- 스냅샷을 사용해 Google Sheets 내용을 복구할 수 있다.

#### 릴리스

- 릴리스는 데이터와 번역 스냅샷을 원자적인 하나의 묶음으로 관리한다.
- 릴리스에는 고유 ID, 이름, 설명, 생성자, 생성 시각과 포함 스냅샷 목록이 있다.
- 릴리스 생성 시 모든 갱신 규칙, 누락 번역, 중복 키, 삭제 후보, 충돌을 검사한다.
- 검증에 실패한 릴리스는 개발 또는 라이브 채널에 지정할 수 없다.
- 개발 채널과 라이브 채널은 각각 하나의 현재 릴리스를 가리킨다.
- 라이브 릴리스는 직접 수정하지 않고 새로운 릴리스를 만들어 교체한다.
- 과거 릴리스를 현재 채널로 다시 지정하는 롤백을 지원한다.
- 개발에서 라이브로 승격할 때 승인 권한과 감사 로그를 요구한다.

```text
공동 편집 중인 Google Sheets
          ↓ 갱신 및 검증
불변 스냅샷
          ↓ 묶음 생성
개발 릴리스
          ↓ 테스트 및 승인
라이브 릴리스
```

#### Unity 제공 방식

Unity가 공동 편집 중인 번역 Spreadsheet를 직접 읽지 않도록 한다. 다음 중 하나를 기술 검증 단계에서 선택한다.

1. 권장: 개발·라이브 채널별 릴리스 아티팩트 또는 API를 Unity에 제공한다.
2. 호환: 관리 도구가 개발용·라이브용 출력 Spreadsheet에 승인된 스냅샷의 일반 값만 게시한다.

어느 방식을 선택하든 Unity가 가져가는 데이터는 특정 릴리스 ID로 재현할 수 있어야 한다.

## 11. Google Sheets 연동 원칙

- Spreadsheet는 Google의 불변 `spreadsheetId`로 식별한다.
- 탭은 이름뿐 아니라 `sheetId`도 함께 저장한다.
- 갱신 미리보기 생성 전후에 원본 문서 버전과 데이터 해시를 확인한다.
- 원본이 미리보기 이후 변경되면 기존 미리보기의 반영을 차단한다.
- 읽기 요청은 Spreadsheet와 탭별로 묶어 API 호출 수를 줄인다.
- 쓰기 요청은 대상 Spreadsheet별 배치로 실행한다.
- 일반 값 기록은 `RAW` 모드를 사용한다.
- Google API 일부 성공 가능성에 대비해 셀별 결과와 복구용 스냅샷을 남긴다.
- 외부에서 시트 이름이나 구조가 변경되면 규칙 오류로 표시하고 자동 추측해 쓰지 않는다.

## 12. 보안과 감사

- 회사 Google Workspace 도메인 사용자만 로그인할 수 있다.
- Google OAuth scope는 필요한 최소 범위로 제한한다.
- 서비스 계정은 관리 대상 문서에 명시적으로 공유된 권한만 사용한다.
- 액세스 토큰과 갱신 토큰은 브라우저 저장소에 장기 보관하지 않는다.
- 셀 데이터와 스냅샷은 사내 인프라에만 저장한다.
- 사용자 입력과 Google Sheets 값을 HTML로 직접 렌더링하지 않는다.
- 로그에 전체 셀 내용을 기본 기록하지 않고 위치, 해시, 변경 유형을 우선 기록한다.
- 마이그레이션, 갱신, 상태 변경, 릴리스 생성, 라이브 승격, 롤백을 감사 로그에 기록한다.
- 라이브 승격과 스냅샷 삭제는 별도 권한을 요구한다.

## 13. 오류 및 충돌 처리

| 상황 | 처리 |
|---|---|
| 원본 접근 권한 없음 | 갱신을 중단하고 대상 문서와 필요한 권한을 표시한다. |
| `IMPORTRANGE` 결과 오류 | 일반 값 변환을 차단하고 오류 셀을 보고한다. |
| 원본 탭 또는 셀 없음 | 규칙 오류로 표시하고 자동으로 다른 셀을 선택하지 않는다. |
| 중복 번역 키 | 대상 반영과 릴리스 생성을 차단한다. |
| 미리보기 이후 원본 변경 | 기존 미리보기를 폐기하고 재실행을 요구한다. |
| 대상 Korean 수동 변경 | 덮어쓰기 전에 충돌로 표시한다. |
| 일부 Google API 쓰기 실패 | 작업을 실패 또는 부분 실패로 표시하고 스냅샷 복구를 제공한다. |
| 재번역 미완료 | 정책에 따라 라이브 승격을 차단하거나 승인 가능한 경고로 표시한다. |
| 라이브 배포 실패 | 이전 라이브 릴리스를 유지하고 실패 로그를 기록한다. |

## 14. 비기능 요구사항

### 14.1 성능

- 현재 3,710개의 수식 분석과 마이그레이션 미리보기를 처리할 수 있어야 한다.
- Google API 호출은 셀별 호출이 아니라 Spreadsheet·탭·범위별 배치를 사용한다.
- 일반적인 갱신 미리보기는 10초 이내를 목표로 한다.
- 긴 작업은 진행 상태를 표시하고 사용자가 안전하게 취소할 수 있어야 한다.
- 동일한 작업의 중복 실행을 방지한다.

### 14.2 신뢰성

- 모든 쓰기 작업은 멱등성을 가져야 한다.
- 스냅샷 생성에 실패하면 갱신을 시작하지 않는다.
- 갱신 결과는 원본 버전, 대상 변경 전후 버전과 연결한다.
- 개발·라이브 채널 전환은 데이터베이스에서 원자적으로 처리한다.
- 서버 재시작 후 실행 중이던 작업의 상태를 복구하거나 명확히 실패 처리한다.

### 14.3 사용성

- 모든 변경 화면에서 원본 위치, 대상 위치, 기존 값, 신규 값을 함께 표시한다.
- Spreadsheet와 탭 이름에서 원본 Google Sheets를 바로 열 수 있다.
- 개발과 라이브 상태를 색상뿐 아니라 텍스트로 명확히 구분한다.
- 위험한 작업은 영향 건수와 스냅샷 생성 여부를 표시한다.
- 오류 메시지는 원인, 영향을 받은 위치, 사용자가 할 수 있는 조치를 포함한다.

10. 데이터와 번역 스냅샷으로 개발 릴리스를 만든다.
11. 검증을 통과한 개발 릴리스를 라이브로 승격한다.
12. Unity에서 개발과 라이브의 서로 다른 릴리스를 받아올 수 있는지 확인한다.
13. 이전 라이브 릴리스로 롤백하고 동일한 데이터가 복원되는지 확인한다.

## 18. MVP 제외 범위

- 웹사이트 내부에서 Google Sheets와 동일한 셀 편집기 제공
- 웹사이트에서 Google Spreadsheet 또는 탭 생성·삭제
- 사용자가 임의 JavaScript를 작성해 실행하는 기능
- 한국어 이외의 언어 자동 번역
- 번역문 자동 생성
- Google Sheets의 실시간 공동 편집 기능 대체
- 모든 종류의 Google Sheets 수식 제거
- Excel 파일 지원
- 모바일 전용 편집 UI

## 19. 결정이 필요한 항목

1. Unity가 현재 Google Sheets를 언제, 어떤 방식으로 가져오는가?
2. Unity에는 릴리스 API·파일을 제공할지, 개발·라이브 출력 Spreadsheet를 제공할지?
3. 각 데이터 Spreadsheet에서 안정적인 행 키로 사용할 열은 무엇인가?
4. 원본 항목 삭제 시 번역 행도 삭제할지, 삭제 후보로 유지할지?
5. 재번역 필요 항목이 하나라도 있으면 라이브 승격을 차단할지?
6. 재번역 완료를 값 변경만으로 판단할지, 사용자의 명시적 확인을 요구할지?
7. 번역 언어 목록과 열 이름이 모든 탭에서 동일한가?
8. 스냅샷 보존 기간과 삭제 권한은 어떻게 정할지?
9. Google API 접근은 사용자 OAuth와 서비스 계정 중 어떤 방식으로 운영할지?
10. 라이브 승격 시 필요한 승인자 수와 역할은 무엇인가?
