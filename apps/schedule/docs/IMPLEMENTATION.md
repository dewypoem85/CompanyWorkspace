# 확정 계획 및 구현 추적

## 2026-09-21 단일 업무 일정 및 시트형 버전 기록

- 업무 날짜는 시작일·종료일 한 쌍만 사용한다. 사용되지 않던 실제 시작일·실제 종료일 입력, 비교 토글, 별도 조회 기준과 API 필드를 제거한다.
- 업무 막대와 완료 업무 테두리는 모두 실선으로 표시한다. 보기 설정에는 상세 보기와 행 높이만 남기며 기존 담당자·책임자·관리자 수정 권한 및 버전 충돌 검사를 유지한다.
- 기동 스키마 전환은 `ActualStartDate`·`ActualEndDate` 열과 관련 인덱스를 제거하며 재실행할 수 있다. 업무 ID·시작일·종료일·본문·댓글·첨부·이력은 유지한다.
- 사용자 제공 시트 형식으로 프로젝트별 버전/최종/최초 업데이트/주요 내용 표를 구현했다. 기본 버전 770과 770.1, 770.2 같은 마이너를 묶고 숫자로 정렬한다. 최초 업데이트와 주요 내용은 기본 버전 기록을 기준으로 하며 최종은 가장 높은 등록 마이너를 표시한다.
- 기본 버전 건너뜀은 버전과 최종 칸을 빨갛게 표시한다. 각 기록에 안정·불안정·롤백 상태, 패치 내용, 문제·조치 내용, 복귀 버전, 해결된 후속 마이너를 저장한다. 문제/롤백/건너뜀은 사유 필수이며 마이너에서 기본 버전 건너뜀을 지정할 수 없다.
- 관리자·본인 부서 책임자가 기록을 관리하고 직원은 보이는 프로젝트의 기록을 조회한다. 버전 번호는 참조 보존을 위해 등록 후 고정된다. 모든 저장의 스냅샷과 작성자를 남겨 상태/내용 변경 이력을 확인한다. 표·마이너·변경 이력은 50개씩 추가 조회한다.
- Releases/ReleaseRevisions 테이블을 만드는 이전은 트랜잭션으로 실행하며 재실행해도 기존 데이터를 덮어쓰지 않는다. 기존 시트 데이터는 자동 가져오지 않는다.
- 단일 날짜 구간과 실제 날짜 열 제거·재실행, 권한 회수, 비공개 프로젝트, 숫자 마이너 정렬, 문제 해결 연결, 중복/충돌/롤백을 자동 검사한다.

## 2026-09-08 일정 가독성·연속 조회·동료 등록

- 주요 일정에 일반·검수·업데이트 타입을 추가하고 고정된 주요 일정 행에 배지·테두리·배경과 상세 내용 미리보기를 표시한다. 좁은 칸은 두 줄 제목과 클릭 상세를 사용한다.
- 기존 일정은 일반 타입으로 유지한다. 타입 열 추가는 재실행 가능하며 구버전 PUT의 타입 생략은 기존 값을 보존한다.
- 화면 표시 1·2·4주와 요약 행 높이 36~100px를 브라우저에 저장한다. 초기에는 표시 구간과 다음 한 주를 읽고, 좌우 스크롤 시 새 주만 추가 요청한다. 최대 8주만 유지하고 반대편을 비우므로 조회 날짜에는 기간 상한을 두지 않는다. 주별 API 요청과 업무 ID 병합으로 장기 업무의 중복 표시를 막는다.
- 조회 실패 시 새 캐시를 부분 반영하지 않는다. 재시도·30초 갱신·창 복귀에는 로드된 구간을 다시 읽는다. 필터와 회사 디렉터리 변경 시 캐시를 분리하거나 갱신한다.
- 일반 직원도 보이는 활성 직원의 업무를 신규 등록할 수 있다. 담당자에게 기존 통합 알림 경로로 한 번 알리고 자기 알림은 생략한다. 등록자는 자동으로 수정 권한을 얻지 않으며 기존 본인·부서 책임자·관리자의 수정 규칙을 유지한다. 비공개·공유·비활성·접근 불가·마스터 계정 제한을 유지한다.
- 부서 행 배경은 기획(황토)·개발(파랑)·아트(보라)로 구분하고 업무 카드 전체 실선 테두리와 옅은 배경에 프로젝트 색상을 적용한다.
- 프런트엔드 19개, 서버 16개 테스트로 주별 증분 요청·실패 원자성·8주 메모리 상한·연도 경계·타입 이전·동료 등록 알림 및 수정 권한 회수를 검증했다. 로컬 브라우저에서 가로 스크롤 추가 로딩·4주 축소·행 높이 저장·검수 타입 저장·일반 직원의 동료 업무 등록을 확인했다.

## 2026-09-08 주요 일정 상세 내용

- 현재 Portal 공통 워크스페이스·테마·프로필·통합 알림 구조를 기준으로 주요 일정 상세 입력과 직원용 읽기 화면을 추가했다.
- `Milestone.description`은 선택 입력인 일반 텍스트이며 최대 10,000자와 줄바꿈을 지원한다. HTML은 실행하지 않고 문자 그대로 표시한다. 별도 댓글·첨부는 추가하지 않는다.
- 기존 `GET/POST/PUT /api/milestones`에 필드를 추가했다. 구버전 PUT이 필드를 생략하면 기존 상세 내용을 유지하고, 빈 문자열을 명시하면 지운다. 기존 관리 권한과 버전 충돌 검사를 유지한다.
- 시작 시 `Milestones.Description TEXT NOT NULL DEFAULT ''` 열을 한 번 추가한다. 기존 ID·제목·날짜·프로젝트·버전은 보존하며 재실행해도 상세 내용을 덮어쓰지 않는다. 이전 앱으로 롤백해도 추가 열을 삭제할 필요가 없다.
- 최신 공통 프로젝트 선택기와 비공개 프로젝트 접근 제어를 유지했다. 프런트엔드 16개 및 서버 15개 테스트 통과. 브라우저에서 기존 일정에 여러 줄 상세 내용을 저장하고 일반 직원으로 다시 열어 읽는 흐름을 확인했다.
