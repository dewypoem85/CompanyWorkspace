# 저장소 작업 지침

## 작업 전 확인

- 코드나 문서를 수정하기 전에 `docs/PROJECT_CONTEXT.md`를 먼저 읽습니다.
- 구조, 알림 흐름, 권한, 환경 변수, DB 스키마, 페이지 또는 운영 절차가 변경되면 관련 Markdown 문서도 같은 작업에서 함께 갱신합니다.

## 커밋 메시지 규칙

1. 커밋 제목은 `fix:`, `feat:`, `chore:`, `docs:`, `refactor:` 같은 영어 Conventional Commits 접두사로 시작합니다.
2. 영어 접두사 뒤의 제목은 한국어로 작성합니다.
3. 제목만으로 무엇을 변경했는지 알 수 있도록 구체적으로 작성합니다.
4. 가능한 경우 제목 아래에 빈 줄을 넣고, 변경한 내용을 한국어 상세 본문으로 함께 작성합니다.
5. 여러 항목을 변경한 경우 상세 본문을 항목별로 나누어 작성합니다.
6. 단순히 `수정`, `업데이트`, `변경`처럼 변경 내용을 알 수 없는 제목은 사용하지 않습니다.

예시:

```text
fix: Discord 개인 DM 링크 형식 통일

- 채널 웹훅과 개인 DM이 동일한 공통 포맷터를 사용하도록 변경
- 알림 하단에 연차 관리 페이지 바로가기 링크 추가
- 관련 프로젝트 문서의 알림 흐름 설명 갱신
```
