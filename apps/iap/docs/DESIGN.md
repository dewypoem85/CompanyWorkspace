# 상품 관리 시스템

## 불변 조건

Google/Apple에서 이미 존재하는 모든 상태의 상품은 일반 작업에서 쓰기 요청 0건이다. 조회 실패는 부재가 아니다. 기존 상품 변경은 상품/스토어/사용자/필드/원격 스냅샷에 연결된 10분짜리 일회성 승인을 사용한다. 삭제/ID/타입 변경은 지원하지 않는다.

신규 생성 성공이 영구 기록된 작업만 고정된 후속 단계를 수행한다. 생성 응답 유실과 요청 도중 프로세스 종료는 미확정으로 중단하고 자동 인계/재생성하지 않는다. 실행 중 승인 상태 변경과 재시도는 DB에서 직렬화한다.

Steam은 현재 PlayFab 전체 카탈로그 덮어쓰기를 허용한다. 선택 상품을 병합하고 미선택 상품/알 수 없는 필드를 유지한다. 이전 원문을 보관하며 외부 변경이 감지되면 중단한다. PlayFab API는 CAS가 없으므로 외부 콘솔과의 동시 편집을 잠글 수 없다.

## 데이터와 구성

회사 포털 프로젝트 → 프로젝트별 Products 5개 식별 열 → 불변 snapshot. 웹은 이름·설명·번역·유형·CSV 가격·설정·계획·작업·감사를 소유한다. 시트 재가져오기는 웹 설정을 보존한다. 게임 데이터는 보상/구매이력/조건/UI를 소유한다. 원격값은 별도 보관한다. 제공받은 가격 CSV는 파일 해시로 버전을 고정한다. 상품 상세에서 KOR 가격을 바로 선택하면 같은 행의 국가별 소비자가격에서 Google·Steam 가격과 내부 스냅샷을 자동 생성한다. 별도 가격 생성·확정 화면은 없다. 가격 선택은 기존 모바일 상품을 갱신하지 않는다. 자세한 현재 규격은 DATA.md를 따른다.

목록 숨김은 프로젝트·상품 키에 묶인 웹 전용 설정이다. 원격 조회 상태는 세 플랫폼을 모두 확인해 분류하며 불확실한 응답은 별도 상태로 유지한다. 신규 업로드 화면은 세 플랫폼을 기본 선택한다.

React/TypeScript, Express, PostgreSQL, DB 작업 워커. SSO audience iap, iap.access/iap.publish 권한. 모든 외부 키는 서버의 파일 참조로만 제공한다. 운영과 로컬 데모 연결은 상호 배타적이다.

## 검증과 단계별 전달

기반 → 시트/프리셋 → 서버 보호/승인/복구 → 모바일 연결 → Steam → Unity/Portal. 각 단계 관련 테스트 후 커밋/푸시한다. 모바일 운영 쓰기는 실제 테스트 상품의 충돌/응답 유실 검증 기록이 있는 연결에서만 활성화한다.
