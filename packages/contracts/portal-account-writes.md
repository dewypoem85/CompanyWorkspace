# Portal 회사 계정 쓰기 계약

직원 관리의 `Add`와 `BulkUpdate` native POST는 같은 `account-fields.json` 필드 집합을 사용한다. 신규·기존 계정에서 계정 유형, 활성 상태, 이름, Google 이메일, 부서, 입사일, 생일, 참여 프로젝트, 비공개 여부, 회사 역할과 시스템 권한 중 하나라도 빠진 별도 편집기를 만들지 않는다. 화면에 보이는 역할·권한은 서버 인가를 대신하지 않는다.

## 입력과 인가

- 현재 중앙 세션의 관리자만 일반 직원을 관리한다. 관리자·마스터 역할의 부여 및 변경, 관리자 계정 대상 변경은 회사 마스터만 할 수 있다. 현재 마스터 자신과 마지막 활성 마스터를 비활성화하거나 강등할 수 없다.
- 공용 테스트 계정은 관리자·마스터 역할과 연차 투영을 가질 수 없다. 실제 직원은 유효한 입사일이 필요하다. 비공개 직원·비공개 프로젝트도 관리자 화면에서만 노출하고 서버에서 다시 권한을 확인한다.
- 이메일은 trim·소문자 정규화 후 전체 계정에서 고유해야 한다. 이름·이메일 길이, 계정 유형, 역할, 활성/비공개 bool, 입사일·선택 생일, 부서·프로젝트 ID와 시스템 권한은 공통 필드 카탈로그 및 현재 선택 목록으로 검증한다. 생일은 연도 없는 정확한 `MM-DD`만 받고 공용 계정에서 제거하며 직원 관리와 Leave 달력 표시 외부에 공개하지 않는다.
- 일괄 저장은 변경된 행만 전송하고 `updates.Index`, 문자열 계정 ID, 문자열 64비트 `UpdatedAtTicks`, 원래 전체 필드 baseline을 유지한다. 최대 500개, 중복 ID 없음, 모든 대상 존재와 행별 버전 일치를 쓰기 전에 검증한다. JavaScript Number로 ID나 tick을 변환하지 않는다.

## 저장과 확인

- 신규 계정은 사용자·부서/프로젝트 관계와 필요한 Leave projection outbox를 한 DB 트랜잭션에서 저장한다. `workspace-form-v1`의 `saved` 응답은 서버가 다시 만든 문자열 ID·문자열 tick·전체 공통 필드를 포함한다.
- 일괄 저장은 대상 전체를 같은 트랜잭션에서 비교·적용하고, 변경된 실제 직원의 Leave projection을 큐에 넣은 뒤 커밋한다. 응답의 모든 제출 계정에 서버 정규화 전체 필드와 새 tick, 전체 지표가 있어야 저장 기준을 갱신한다. 입력을 그대로 성공 영수증으로 사용하지 않는다.
- `CompanyForm`과 계정 생성/일괄 편집 어댑터가 확인·전송·관찰을 소유한다. 성공 영수증을 완전히 검증하기 전 초안을 지우거나 버전을 올리지 않는다. 일괄 충돌 비교 GET은 `portal-account-reads.md`의 별도 공통 read session을 사용한다.

## 실패와 초안

- 확실한 입력 오류는 422 `invalid`, 존재하지 않거나 오래된 계정은 409 `conflict`, 현재 권한으로 볼 수 없는 비교 대상은 403 `denied`다. 전송 후 결과를 확정할 수 없거나 불완전·손상된 응답은 `unknown`으로 잠그고 자동 재전송하지 않는다.
- native fallback은 허용된 공통 필드만 원문으로 보존한다. 안전하게 표현할 수 없는 값, 커밋 여부를 확정할 수 없는 실패, 대상/버전 충돌에서는 저장 UI를 잠그고 새 탭 조회를 안내한다. antiforgery, 중앙 세션, 서버 트랜잭션은 그대로 유지한다.
- 필터·상세 열기·비공개 표시는 저장이 아니다. 페이지 이탈, 계정/범위 변경, 늦은 응답은 현재 초안·다른 계정의 기준값을 덮어쓰지 않는다.

이 계약은 Portal 계정 쓰기의 현재 경계를 고정한다. 다른 서비스 DB를 직접 합치거나 운영 계정, SSO, 배포 성공을 보장하지 않는다. 서버 통합·브라우저·구조 변이 검사를 함께 유지한다.
