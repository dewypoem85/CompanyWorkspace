# 한 문서의 복수 폼 조정

`CompanyForm.createSession()`은 확인창부터 저장 결과 판정까지 한 번에 하나의 작업만 진행하도록 조정한다. 공통 전송은 `CompanyForm.createTransport`와 native 어댑터 `attach`가 소유하고 각 도메인 어댑터는 전체 저장 응답을 검증한다. 세션 자체는 fetch·저장·인가·자동 재시도를 하지 않는다.

## API와 수명주기

- 한 문서의 관련 편집기는 같은 인스턴스를 공유한다. Leave는 `window.LeaveFormSession ||= window.CompanyForm.createSession()`을 사용한다. 각 어댑터는 고유 문자열 owner와 실제 미저장 초안 판독 함수를 `track(owner, hasDraft)`으로 등록한다. 중복 owner/잘못된 등록은 거부한다.
- `begin(owner, resources)`가 반환한 lease를 얻은 작업만 확인을 시작한다. 이미 다른 확인/전송이 진행 중이거나 문서가 무효화됐거나 소모된 기준값이면 null이다. 같은 owner도 두 번째 lease를 얻지 못한다. `blocked(owner)`는 화면 상태용이며 자기 lease는 제외하므로 이를 begin 대신 사용하면 안 된다.
- `resources`는 도메인이 만든 불투명 문자열 키 배열이다. Leave 신청은 `leave-request:{문자열 ID}:{제출 전 전체 스냅샷}`, 외부 일정은 별도 `external-schedule:` namespace를 쓴다. 직원 취소와 관리자 강제 삭제가 같은 신청의 같은 기준값을 공유한다. 큰 ID를 Number로 변환하지 않는다.
- 확인 후에도 입력/대상/로그인 범위 및 `lease.current`를 검사하고 공통 폼으로 전송한다. 실제 전체 응답을 검증한 공통 폼의 onSettled 결과에서만 lease를 `saved`로 마친다. 확인 취소나 전송 준비 실패는 요청 전 `cancelled`, 확실한 422 invalid만 `invalid`로 마친다. 이미 보낸 요청을 cancelled로 해제하면 안 된다.
- `saved`는 제출 전 resource 기준값을 소모하고 다른 owner의 쓰기를 풀어준다. 이미 처리한 신청의 오래된 버튼/별도 표시 경로도 같은 resource로 막는다. 새 서버 기준값은 다른 resource지만 실제 서버의 기존 소유권/스냅샷 검증은 계속 필수다.
- 기본 소비자는 나머지 권한/충돌/손상 응답/통신 실패/timeout 등을 보수적으로 `unknown`으로 종료한다. 현재 문서의 모든 owner를 잠그며 자동으로 다시 보내거나 초안을 지우지 않는다. 별도 GET으로 결과를 확인하고 새 문서에서 재개한다. HTTP 거부가 DB 롤백을 보장한다는 뜻은 아니다.
- 이전 lease의 늦은 finish는 새 lease를 종료하거나 잠금을 풀지 못한다. 범위 변경은 기본적으로 세션을 무효화한다. 아래 명시적 복구를 사용하지 않는 기존 native 소비자의 잠금 정책은 유지한다. 실제 pagehide는 dispose하며 bfcache의 persisted pagehide는 현재 세션을 유지한다. dispose는 리스너와 owner를 정리하고 늦은 완료를 거부한다.
- `subscribe`는 상태 변화를 microtask로 모아 전달하며 개별 뷰 오류가 다른 뷰의 갱신을 막지 않는다. 반환한 해제 함수를 어댑터 정리 시 호출한다. 초안 판독 오류는 초안 있음으로 처리한다. `hasDraftExcept(owner)`는 지정한 owner만 제외하고 현재 등록된 판독 함수를 읽는다.
- `revision`은 확인 작업이 시작되거나 문서가 무효화/해제될 때 증가한다. GET은 시작 시 값을 캡처하고 성공/실패 후 다시 비교한다. 저장이 끝나 pending=false가 된 뒤 도착한 오래된 조회도 DOM 교체나 전체 페이지 redirect를 하지 못하게 한다. 이것은 서버 데이터 버전이 아니라 현재 문서의 작업 순서다.

## 명시적으로 연결한 React 업무 편집기

- `documentSession(key)`는 같은 문서에서 key별 세션을 재사용한다. SPA 편집기 unmount/remount로 unknown 잠금을 초기화하지 않는다. `track`의 반환 함수를 unmount 때 호출하며 전송 중 owner 해제는 세션을 무효화한다.
- 서버가 첫 쓰기 전 충돌임을 보장하는 정확한 409/conflict만 `finish('conflict')`로 처리한다. saved처럼 이전 resource를 소모하지만 문서 전체를 unknown으로 잠그지 않는다. 실제 최신 기준 대조와 사용자 비교/재선택은 도메인 책임이다. 기존 Leave 소비자 정책을 자동 변경하지 않는다.
- 복구 기능을 선택한 소비자는 **모든 전송 직전** `markSent()`로 기록하고 false이면 전송하지 않는다. `recoverScope()`는 보내지 않은 작업/idle의 범위 무효화만 해제한다. 원래 계정·현재 권한·정확한 대상/기준을 명시적으로 재검증한 도메인만 호출한다. 이 함수 자체는 인증하지 않는다.
- unknown, sent 상태의 범위 변경/owner 해제, 실제 pagehide는 복구되지 않는다. 복구 시 revision은 증가하며 이전 lease와 소모된 resource는 되살리지 않는다. 새 계정의 GET 성공을 이전 초안 재사용 허가로 바꾸지 않는다.

## Leave 소비자 (기존 정책 유지)

- 신청 Apply는 확인된 신청의 입력을 읽기 전용으로 유지하지만 다른 폼을 잠그지 않는다. 저장된 신청 폼이 아직 보여도 달력 클릭은 날짜 재선택이 아닌 상세 보기로 동작한다. 같은 문서에서 같은 신청을 반복 생성하지 않는다.
- 직원 취소/철회는 처리한 신청 기준값만 소모한다. 다른 신청은 이어서 처리할 수 있고 같은 신청의 강제 삭제 버튼은 오래된 스냅샷으로 실행되지 않는다.
- 외부 일정 저장 후에는 검증된 ID·새 fingerprint·정규화 입력을 편집기에 반영하고 기준 초안으로 삼는다. 값이 그대로면 재전송하지 않는다. 수정하면 새 ID/버전으로 update하며, 이미 생성한 일정을 다시 create하지 않는다. 다른 일정/새 일정으로 전환하거나 초기화하는 명시적 동작과 자동 날짜 기본값 갱신을 구분한다.
- 관리자 추가는 확인된 입력을 그대로 반복 제출하지 않는다. 변경된 입력 또는 명시적 초기화로 새 의도를 시작할 수 있다. 삭제는 전체 신청의 오래된 기준값만 소모하고 다른 추가/삭제 사유 초안은 유지한다.
- 다른 초안이 있으면 자동 문서 이동을 하지 않는다. 각 owner가 확인된 저장 기준으로 자기 초안을 계산하므로 이미 저장한 다른 폼을 미저장으로 오인하지 않는다. 등록되지 않은 기존 POST 입력은 보수적인 값 비교로 보존한다.
- 한 owner의 불확실한 쓰기, 진행 중 DOM 제거 또는 계정 변경은 다른 편집기에서도 쓰기를 막는다. 입력은 복사/확인할 수 있도록 유지한다. 달력/내역 GET은 pending·invalid와 revision을 확인한다.

## 한계와 검증

이 세션은 현재 문서 메모리 안에서만 동작한다. 다른 탭·구형 native 문서·새로고침을 포함한 영구 멱등성, DB 트랜잭션, CAS 또는 서버 롤백을 제공하지 않는다. 서버 인가/정확한 기준값/업무 규칙과 각 어댑터의 전체 ACK 검증을 대체하지 않는다. 여러 폼을 하나의 DB 트랜잭션으로 합치지 않는다. 저장 확인 후 요약·잔여량·기존 달력 내용을 임의로 계산해 덮어쓰지 않으며 최신 내역 링크 또는 마지막 초안 저장 후 GET으로 확인한다.

`form-session.test.mjs`는 상호 배제·초안·완료/미확정·stale lease·resource namespace/기준값·범위/해제/bfcache·구독·조회 revision을 검사한다. `leave-form-session.spec.mjs`는 실제 격리 Razor와 공통 자산으로 신청/관리자 추가/외부 일정의 여섯 저장 순서, 두 테마/폭, 동일 신청의 취소/삭제 차단, 외부 일정 재편집, 두 번째 쓰기의 실패/수정·scope·이탈 및 늦은 GET 200/500을 검증한다. 실제 서버 계약/SQLite 검사는 각 기존 도메인 통합 검사가 담당한다. 구조 변이 검사는 대표적인 연결 누락을 잡을 뿐 완전한 파서나 인가 증명이 아니다.
