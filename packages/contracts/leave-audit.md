# 연차 감사 로그 조회·표시 계약

`Admin/AuditLogs`는 기존 관리자 전용 GET 조회다. 쓰기 API, 감사 원문, 작업자 목록의 정책과 서버 인가를 변경하지 않는다. 검색·페이지 이동은 `audit-logs.js`에서 관리하고 공통 UI를 연결한다.

- 입력·라벨·버튼·표는 `cw-form-*`, `cw-button`, `cw-data-table`을 사용한다. 표 스크롤에는 이름과 키보드 진입점을 제공하고 기존 모바일 카드 전환을 보존한다. 작업 종류는 info `cw-state-pill`을 사용하고 앱별 배지 색·크기를 소유하지 않는다. 상세의 색상은 공통 surface/text/line/active 토큰을 사용한다.
- 상세는 `CompanyDisclosure.attach(area,{single:true})`가 소유한다. 한 행만 열고 버튼의 ARIA/문구와 패널 hidden을 함께 갱신한다. 직접 toggle 핸들러를 다시 추가하지 않는다. 사유·JSON·ID는 Razor가 인코딩한 원문을 표시하며 JavaScript 숫자 변환이나 JSON 재직렬화를 하지 않는다.
- 작업자 사진은 기존 로컬 직원→회사 직원 매핑과 `CompanyEntityDisplay`를 사용한다. 사진이 없는 경우 이름 첫 글자를 남기며 감사에 기록된 작업자 이름은 그대로 유지한다. 공통 컨텍스트에 없는 사진을 별도 계정 조회로 우회하지 않는다.
- 공통 `CompanyReadSession`의 `leave-audit` 채널이 15초 관찰 제한·취소·최신 요청 판정을 소유한다. 같은 출처의 감사 GET만 허용하고 자동 redirect를 받지 않는다. 검색 조건 변경·새 조회·문서 해제는 이전 요청을 취소한다. 취소를 무시하는 늦은 body 읽기와 이전 finally도 새 결과를 덮어쓰지 않는다.
- 정상 응답은 단일 감사 영역, 현재 로컬 직원 소유자, 작업/작업자/대상/표시 개수, 필수 폼·표와 script 부재를 대조한 뒤 교체한다. 이는 전체 서버 HTML의 보안 sanitizer나 모든 행/페이지의 별도 서명 검증이 아니다. 서버의 페이지 정규화·범위 조정은 유지한다.
- 일시 오류·손상/다른 검색 조건 응답·timeout은 마지막 정상 목록과 입력을 유지하고 `CompanyState`의 오류 및 명시적 같은 조건 GET 재시도를 제공한다. 오류를 빈 결과로 바꾸거나 강제로 다른 페이지로 보내지 않는다.
- 401/403·다른 직원 소유자·`workspace-entity-scope-change`는 이전 감사 본문을 제거하고 공통 denied 상태를 표시한다. 명시적으로 현재 계정 화면을 다시 열기 전에는 재조회하지 않는다. bfcache 보관은 진행 중 읽기만 취소하며 이후 계정 확인은 기존 셸이 담당한다.
- JavaScript가 없으면 기존 GET 폼과 페이지 링크가 동작한다. 상세는 noscript에서 모두 펼쳐 읽을 수 있게 하고 무동작 펼치기 버튼은 숨긴다.

## 검증

`LeaveAuditTests`는 격리 TestServer/SQLite에 합성 감사 로그를 넣어 필터·페이지·표시 개수·큰 정수/인코딩·회사 연결 오류·비활성 계정 거부를 확인하고 실제 Razor fixture를 만든다. `leave-audit.spec.mjs`는 그 HTML과 실제 공통 자산으로 PC/모바일·두 테마·작업 pill 계산 색·단일 펼치기/키보드·입력 크기·native fallback·실패/재시도·범위/해제/늦은 응답을 검사한다. 운영 감사 데이터에 연결하거나 쓰지 않는다.

공통 CSS/런타임 전체, 다른 연차 화면의 필드·표·폼과 원격 배포 전환까지 이 계약 하나로 완료했다고 보지 않는다.
