# 시트 실행 저장 계약

수식 마이그레이션과 한국어 원문 갱신은 React 화면의 직접 `fetch`나 조회용 `api.ts`를 사용하지 않는다. `useSheetActions`가 공통 `CompanyDialog`에서 검토 대상을 고정한 뒤 generated `CompanyForm` transport로만 POST한다. transport의 30초 관찰 제한, 동일 출처·수동 redirect, 공통 media type 및 계정 변경/문서 해제 처리를 유지한다.

- 수식 전환 명령은 정확한 분석 ID와 `수식 제거`, 한국어 갱신 명령은 정확한 문서·미리보기 ID와 `한국어 갱신`을 전송한다. 확인창이 열린 동안 화면·권한·설정·분석/미리보기 객체 또는 그 전체 직렬화 결과가 바뀌면 보내지 않는다.
- `/api/config`의 문자열 actor ID를 그대로 보존하고 실행 시 `X-Workspace-Actor`로 보낸다. 분석 ID 또는 미리보기 ID는 `X-Workspace-Sheet-State`에도 담는다. 서버는 요청별로 확인한 회사 세션의 actor 및 본문의 기준 ID와 두 헤더를 정확히 대조한 뒤에만 시트를 읽거나 쓴다. 긴 직원 ID를 숫자로 변환하지 않는다.
- 서버 성공은 `workspace-form-v1` saved envelope로만 반환한다. 도메인 영수증은 작업 종류, 분석 ID 또는 미리보기 ID, 문서 ID와 전체 실행 결과를 포함한다. 클라이언트는 실제로 직렬화되어 전송된 본문과 영수증의 정확한 키·대상·건수·시각·스냅샷을 모두 검증한 뒤에만 완료로 표시한다.
- 확인 입력 오류는 422 invalid, 기준 분석/미리보기 변경은 409 conflict envelope로 구분한다. 인증·권한 거부와 서버 장애는 성공으로 바꾸지 않는다.
- POST를 보낸 뒤 timeout, 이탈, 계정 변경, 잘못된 media type/JSON/영수증이면 반영 여부가 미확정이다. 자동 재전송하지 않는다. 사용자는 현재 시트와 스냅샷을 다시 확인해야 한다.
- 성공 영수증 뒤 설정·분석·스냅샷·필요한 미리보기 후속 조회는 공통 `WorkspaceReadSession`의 `after-write` 한 채널과 30초 관찰 제한을 사용한다. 화면·계정 변경과 문서 해제는 채널을 취소하고 취소를 무시한 늦은 응답도 적용하지 않는다. 후속 조회가 실패해도 쓰기 실패로 바꾸지 않는다. `데이터 다시 확인`은 같은 조회 채널만 사용하며 POST를 반복하지 않는다.

현재 서버의 회사 SSO와 요청별 중앙 세션 확인, 쓰기 허용 설정, 분석/미리보기 해시 충돌 검사, 스냅샷 및 실패 복구 정책은 유지한다. actor와 기준 헤더는 요청 범위 대조이며 영구 멱등성 키나 DB 트랜잭션 revision은 아니다. 브라우저 timeout이 Google 작업을 롤백한다고 주장하지 않는다. 스냅샷 복원 API는 아직 화면에 연결되지 않았으므로 이 계약의 실행 두 종류에 포함하지 않는다.
