# 연차 달력의 직원 표시와 상세 데이터

월간 신청·외부 일정·갱신·생일, 연간 요약과 날짜 상세는 `CompanyEntityDisplay`의 로컬 직원 매핑을 소비한다. 업무 데이터는 Leave의 EmployeeId를 유지하며 회사 프로필 조회에 로컬 ID를 직접 사용하거나 이름으로 계정을 찾지 않는다.

## 식별값과 표시

- `_Layout`의 `data-company-employee-map`은 로컬 ID와 회사 ID를 모두 십진 **문자열**로 직렬화한다. JSON 숫자를 읽은 뒤 문자열로 바꾸는 것은 이미 발생한 64비트 정밀도 손실을 복구하지 못한다.
- Razor 칩과 동적 상세는 같은 `data-company-local-employee`/`cw-entity-avatar`를 사용한다. 매핑·사진이 없거나 이미지 로딩이 실패하면 이니셜을 표시한다. 갱신/제거·이전 이미지의 늦은 오류는 공통 렌더러가 처리한다. 별도 사진 캐시·조회 루프를 추가하지 않는다.
- 사진은 장식용 `aria-hidden`이며 옆의 전체 이름이 의미를 제공한다. 월간/연간 칸의 16/14px 크기는 Leave의 달력 기하다. 모바일에서 숨길 보조 문구의 `span` 선택자는 직계 자식에 한정하여 내부 프로필까지 숨기거나 색을 덮지 않는다.
- 상세는 이름·상태·유형·ID·취소 가능 여부를 각각의 `data-*` 속성으로 전달한다. 이름/공휴일/메모를 `|` 구분 프로토콜로 합치지 않는다. Razor 속성 인코딩과 동적 HTML 인코딩을 모두 유지한다.

## 표시 정책과 업무 경계

- 갱신 일정도 기존 `GetVisibleEmployeesAsync` 결과에서 선택한다. 본인 보기라고 제외된 회사 마스터나 비공개 일반 직원 자신을 별도 목록으로 다시 넣지 않는다.
- 외부 일정의 본인/대신보기는 `ExternalScheduleEmployees`의 실제 허용 대상과 교집합을 사용한다. 전체 관리자 조회에서 퇴사 직원의 과거 외부 일정을 볼 수 있는 기존 정책은 유지한다.
- 일반 직원의 다른 직원 연차는 승인 완료만, 비공개 직원은 관리자에게만 표시하며 공용/회사 마스터는 달력 대상에서 제외한다. 직원 표시 범위와 실제 저장 인가·현재 역할 검증은 별개다.
- 생일은 일반 직원에게 본인 것만 표시한다. 관리자 전체 보기에는 활성 실제 직원과 관리자 본인을 표시하고, 자기것만 보기·대신보기에는 선택 직원만 표시한다. 출생 연도는 렌더링하지 않으며 평년의 2월 29일은 2월 28일로 표시한다. 상세 권한은 `leave-birthday.md`를 따른다.
- 신청·승인·취소·가불·갱신 발생 계산, DB 스키마, 기존 URL/선호 설정 저장 방식과 POST/CSRF는 변경하지 않는다. 연간 요약의 기존 최대 두 항목/나머지 건수 표시도 유지한다.

## 검증

`LeaveCalendarEntityTests`는 실제 Portal SSO/격리 Leave DB와 Razor에서 역할·공개 범위·본인 보기·큰 ID의 문자열 매핑·HTML 인코딩을 검증하고 브라우저용 실제 HTML을 생성한다. `leave-calendar-entities.spec.mjs`는 그 HTML과 실제 공통 자산에 합성 프로필 HTTP를 연결하여 두 너비/테마, 사진 갱신·제거·실패·재열기·로그아웃, 잘못된 로컬 ID 조회 방지와 상세 상태/신청 ID 보존을 검사한다. 계정 데이터나 운영 프로필은 사용하지 않는다.

Leave 레이아웃/전역 CSS 변경은 전체 Leave 브라우저 회귀 대상이다. 이 계약의 완료를 모든 직원 표시 위치, 다른 다섯 서비스, 운영 연계/배포 또는 공통 UI 전체 목표의 완료로 확대하지 않는다.
