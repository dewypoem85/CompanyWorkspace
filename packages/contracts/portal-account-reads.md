# Portal 직원 충돌 비교 조회

직원 일괄 저장이 충돌하면 기존 편집 초안을 유지한 채 서버의 최신 계정·선택 목록·지표를 다시 읽는다. 이 GET은 공통 `CompanyReadSession`의 `account-review` 채널을 사용하며 30초 관찰 제한과 최신 요청 판정을 공통 계층에 맡긴다.

- 응답은 기존 `workspace-form-v1`의 `snapshot` 결과여야 한다. 요청한 모든 계정의 문자열 ID와 64비트 범위를 보존한 `updatedAtTicks`, 전체 공통 필드, 중복 없는 부서·프로젝트 선택지, 모든 지표를 검증한 뒤에만 비교 창을 연다.
- 조회 도중 초안·대상·계정이 바뀌면 결과를 적용하지 않는다. 계정 범위 변경은 `account-review`를 취소하고, 비지속 페이지 이탈은 읽기 세션을 해제한다. 취소를 무시하고 도착한 늦은 응답도 기존 직원 입력·기준 버전·동적 프로젝트 선택지를 바꾸지 않는다.
- 조회 실패와 비교 취소는 기존 초안과 서버 기준값을 보존한다. 비교에서 사용자가 선택한 병합 결과도 아직 저장된 값이 아니며, 명시적인 전체 변경 저장을 다시 실행해야 한다.

구조 검사는 공통 세션·채널·취소·해제·최신 ticket과 사설 timeout 복원을 확인한다. 실제 Chrome 검사는 PC/모바일·라이트/다크의 3-way 비교와 계정 변경 뒤 늦은 응답 배제를 유지한다. 합성 응답은 운영 DB·SSO 성공 증거가 아니다.
