# 팀 일정 업무·댓글 편집 컨트롤

업무 상세의 초기/폴링·업무/댓글 비교·보관/복원/댓글 삭제 전후 조회는 `useTaskDetail`을 공통으로 사용한다. 오류/계정 재확인/초안과 마지막 정상값·전체 응답 검증은 `schedule-detail-reads.md`를 따른다. 확인 중 서버 변경 관찰을 유지하며 스타일 전환과 읽기/쓰기 전환을 구분한다. 업무 생성/수정/상태 저장은 `schedule-task-writes.md`, 댓글 생성/답글/수정은 `schedule-comment-writes.md`, 이미지 업로드는 `schedule-image-uploads.md`, 업무/이미지/날짜 선택 프레임은 `owned-modals.md`의 공통 연결을 사용한다.

## 주요 일정 관리와 보관함

`Settings.tsx`의 목록/기존 수정/신규 등록은 공통 입력·버튼과 `WorkspaceState` 오류/충돌/빈 결과 안내를 사용한다. 제목·유형·날짜·프로젝트·상세 필드는 같은 form에 연결하며 selected 상태는 실제 `aria-pressed`, 삭제는 danger, 저장은 primary, 닫기는 quiet다. 주요 일정 삭제는 공통 확인창에 프로젝트·일정·버전을 표시하고 승인 직전 동일 대상을 재검증한다. 목록 카드는 content 버튼을 사용하고 날짜·프로젝트·유형·긴 제목 배치만 `settings.css`에서 소유한다. 긴 제목과 프로젝트명이 모바일 문서를 넓히지 않아야 한다. 유형 badge 색은 기존 업무 분류 표현으로 남는다.

조회 시작일부터 90일, 기존 날짜 제약/10,000자 원문, 프로젝트 ID·보관된 현재 프로젝트·관리자/부서 책임자 권한과 보관함→업무 상세 URL을 유지한다. 권한 없는 직원의 주요 일정 상세 읽기는 편집 권한과 분리한다. 주요 일정·보관함 목록과 페이지 병합은 `schedule-settings-reads.md`, 등록/수정/삭제는 `schedule-milestone-writes.md`를 따른다. 버전 충돌 후 초안을 유지하고 최신값 선택·새 일정·다른 일정·보관함·닫기·뒤로가기는 공통 비동기 초안 확인에 연결한다. 삭제는 별도 공통 실행 확인과 대상/버전을 재검증한다. 다른 raw 조회/쓰기의 전체 응답·늦은 결과·미확정 수명주기는 여전히 전환 대상이며 상태 렌더러 연결만으로 완료를 주장하지 않는다.

브라우저의 `management common controls` 시나리오는 PC/모바일·두 테마의 계산 스타일, 긴 제목 넘침, 기존 PUT/신규 POST·DELETE의 ID/버전/원문, 충돌·전송 중 비활성, 공통 초안 취소/승인과 보관함 이동을 합성 HTTP로 확인한다. 별도 history 시나리오는 뒤로가기 승인 전 URL/초안 유지와 취소/승인을 검사한다. 정상 저장 fixture는 실제 API 형태를 사용하지만 운영 DB 커밋이나 실패 응답 전체 계약의 증거는 아니다.

## 업무·댓글 편집

`TaskPanel.tsx`, `Editor.tsx`, `CommentComposer.tsx`의 일반 입력과 작업 버튼은 공통 primitive를 사용한다. 업무 편집/이미지 보기의 프레임도 공통 hook에 연결하며 공통 클래스를 붙인 것만으로 나머지 저장 계약까지 완료했다고 판단하지 않는다.

- 업무 제목·담당자·프로젝트·진행 상태와 시작일·종료일 두 날짜 입력은 `cw-form-field`/`cw-form-control`을 사용한다. 업무 그리드는 공통 2열/600px 이하 1열을 소비하며 필수값·길이·날짜 범위·비활성과 실제 ID 제출을 유지한다. 새 업무는 최초 담당자가 참여 중인 활성 프로젝트 가운데 숫자 ID가 가장 작은 항목을 한 번만 기본 선택하며, 미지정과 다른 활성 프로젝트 선택을 허용하고 이후 담당자 변경으로 선택값을 덮어쓰지 않는다. 담당자·프로젝트 검색은 기존 공통 엔티티 선택기에 연결한다.
- 본문·새 댓글·기존 댓글·답글은 같은 `Editor`의 표시 라벨과 textarea를 사용한다. 편집 면적의 최소 140px은 도메인 기하이며 색·포커스·비활성은 공통 소유다. 멘션 원문의 ID·큰 정수 문자열·IME·커서·첨부 목록을 재직렬화하거나 이름으로 추정하지 않는다.
- 취소/저장/수정/이력/보관/복원·이미지 추가는 `cw-button`을 사용한다. 링크 복사·댓글 행 작업은 compact, 보조 작업은 quiet, 삭제·첨부 제거는 danger, 이미지 확대는 content 변형이다. 기존 함수와 이벤트를 그대로 연결한다. 파일 선택 input은 숨겨진 file 컨트롤이며 일반 텍스트 필드가 아니다.
- `DatePicker`의 본문 입력과 열기 버튼, popup의 연도·월/이전·다음·날짜·닫기/지우기/오늘도 공통 primitive를 사용한다. flex 간격을 사용하고 프레임/수명주기는 공통 `useWorkspaceModal`에 연결한다. 날짜 본문·공휴일 조회는 도메인 책임이다.
- 앱의 옛 editor/comment-actions 색과 버튼 크기 덮어쓰기는 제거한다. task/lightbox의 폭·이미지 여백/비율과 본문/기록 장식·다른 미전환 UI의 기하는 별도다. 프레임/두 테마/backdrop은 공통 소유다.

## 동작과 검증

`useTaskActions`의 보관/복원/댓글 삭제 확인, 업무·댓글 충돌 비교 및 댓글의 전체 저장 응답 확인/후속 조회 구분을 유지한다. 업무 생성/수정/상태 전송은 `useTaskWrites`, 이미지 업로드는 `useImageUploads`와 `schedule-image-uploads.md`로 공통화했다. 답글·댓글 수정 편집기 안의 취소와 다른 댓글 편집기로 이동하는 세 경로는 공통 확인창을 사용하며, 댓글 원문·대상·초안 변경 횟수·계정 범위를 승인 직전 다시 확인한다. 상위 새 댓글·답글/수정 초안을 버리고 업무 수정으로 진입하거나 변경 이력을 여는 두 경로도 초안 변경 횟수·업무·프로젝트·계정 범위를 대조하는 같은 공통 확인을 사용한다. 업무 편집 폼의 취소, 브라우저 history 이탈, 본문·댓글의 다른 업무 링크 전환과 업무 창의 닫기 버튼·Escape·외부 닫기도 업무 원문·첨부·댓글 변경 번호·프로젝트·계정 범위를 다시 대조한다. 새 업무 취소는 승인된 요청에 한해 라우트 가드를 한 번 통과시키고, 링크 전환은 실제 다음 업무 열기 성공을 기다린다. 다른 가드가 거부하면 초안을 유지한다. 확인 취소·scope 변경·늦은 승인은 URL과 초안을 유지한다. 댓글 저장 전송 수명주기는 아직 통합 대상이다.

업무 본문 참조 제목의 조회·캐시·scope 폐기는 `schedule-task-reference-reads.md`를 따른다. 참조 제목을 확인하지 못해도 링크는 유지하며, 클릭 후 초안 확인과 실제 대상 상세 이동은 이 문서의 전환 계약을 계속 사용한다.

`schedule-shell.spec.mjs`의 실제 React 번들 검사와 `support/schedule-controls.mjs`는 PC/모바일·두 테마에서 클래스/라벨뿐 아니라 계산 색·크기·비활성, textarea 편집 높이와 날짜 입력/버튼 간격·넘침을 검사한다. 이미지 확대/닫기 후 포커스와 기존 충돌·멘션·첨부·명시적 저장을 함께 검증한다. 엔티티 popup은 별도 소유자이며 native 필드로 세지 않는다. 달력은 별도 루트로 검사하며 실제 viewport 화면을 직접 확인하고 합성 HTTP만 사용한다.

## 날짜 선택과 날짜 이동

`DateNavigation`의 날짜 범위 진입·직접 입력·취소/이동도 동일 primitive를 소비한다. toolbar의 옛 크기 규칙은 제거했으며 상단 필터/보기 설정은 schedule-board-controls.md를 따른다. 기존 원하는 날짜가 포함된 주로 이동, 취소 후 시작일 초기화와 native 필수/유효 날짜 검증을 유지한다.

달력 날짜 버튼은 compact/content/quiet 및 실제 aria-pressed/disabled를 사용한다. 7열·6주, 휴일명과 최소 52px 셀 높이는 도메인 기하이며 선택·비활성·hover를 앱에서 복제하지 않는다. 오늘은 aria-current와 밑줄, 다른 달은 숫자 텍스트의 muted 색을 사용한다. 토요일은 accent, 일요일/공휴일은 danger 텍스트지만 선택·비활성 날짜에서는 버튼의 공통 상태 색을 우선한다. 공휴일 읽기 중/실패·재시도는 WorkspaceState이며 실패해도 날짜 선택/주말 표시는 유지한다.

연도 입력은 blur/Enter로 확정하는 기존 의미를 보존하고 모바일에서 4자리와 스피너 공간을 확보한다. `calendar common controls`는 실제 Tab 확정, 윤일, 종료일 하한·지우기, 잘못된 날짜의 제출 차단, Escape로 자식만 닫기/포커스 복귀와 공휴일 실패·재시도를 검증한다. DatePicker와 날짜 이동창(`DateNavigation`) 모두 공통 중첩 프레임/범위에 연결한다. 공휴일 조회의 응답·취소·계정 범위 계약은 `schedule-date-picker-reads.md`를 따른다.
