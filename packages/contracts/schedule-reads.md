# 팀 일정 초기 정보·보드 조회

## 책임

App은 조회 조건과 페이지/편집 초안을 소유한다. `useScheduleData`는 공통 읽기 세션의 bootstrap/board 채널과 `WorkspaceState`를 연결한다. `scheduleReads`는 서버 응답·페이지 묶음을 검증한다. `timelineData`는 검증된 fetcher를 필수 인수로 받고 별도 raw GET 기본값을 제공하지 않는다. 서버의 중앙 세션·비공개 필터·직원 정책·DB 및 기존 URL은 그대로다.

## 응답과 목록

- bootstrap의 현재 직원/직원 목록·부서·프로젝트·책임자·CSRF 필수값, 안전한 정수 ID/버전과 중복 ID를 확인한다. 비활성·공용·접근 불가 현재 계정은 거부한다.
- 업무의 ID·버전·담당자·작성자·상태·날짜·시각·원문을 검증한다. total은 페이지 길이 이상이고 editableIds/댓글·첨부 건수는 반환한 업무 ID의 부분집합이어야 한다. JSON 원문이 들어 있는 본문을 파싱/재직렬화하지 않는다.
- 주요 일정의 날짜·유형·프로젝트와 부재/공휴일의 날짜·직원·가용 여부를 검증한다. 선택적인 기존 실제 날짜/공휴일 필드는 호환한다.
- 주간 조회는 기존 주별 캐시와 여러 주의 중복 업무 병합을 유지한다. 같은 조건의 확장은 누락 주만 조회한다. 강제 재조회는 묶음 전체가 검증된 뒤 캐시를 교체한다.
- 날짜 미정 목록은 200개 페이지를 이어 읽고, 칸반은 상태별 50개/더 보기 한도를 유지한다. 전체 total을 표시 한도로 바꾸지 않는다. 페이지 간 total 변경·중복 ID·누락은 재조회 오류이며 부분 성공으로 발행하지 않는다. 이것은 서버 스냅샷/원자적 페이지 일관성 보장이 아니다.

## 실패·계정·초안

- GET은 same-origin/no-store이고 HTTP 상태, redirect, JSON content-type 및 전체 값을 확인한다. 본문 해독 전후 AbortSignal을 확인하여 늦은 응답이 로그인 이동을 일으키지 않는다.
- 초기 실패와 빈 목록은 다르다. 같은 조건의 일시 오류에는 마지막 정상 목록을 유지하고 공통 GET 재시도를 제공한다. 조건 변경 뒤에는 이전 조건의 목록을 새 결과처럼 표시하지 않는다.
- 보드 읽기는 30초 관찰 제한을 가지며 30초 폴링은 진행 중 요청을 대체하지 않는다. 오류가 나면 폴링으로 안내를 지우지 않고 명시적 재시도/조건 변경을 기다린다. 초기 정보는 focus/60초에 확인한다.
- 계정/권한 변경·401/403·pagehide는 캐시/목록/CSRF를 무효화한다. 같은 문서의 자동 갱신이나 내비게이션 왕복으로 보드를 되살리지 않는다. 페이지 다시 열기에서 새 계정을 확인한다.
- 이미 열린 편집기는 초안 복구를 위해 유지하지만 새 편집기를 이전 계정 정보로 만들지 않는다. 실제 소유자가 달라지면 보관한 편집기의 권한을 철회하되 owner key를 바꿔 초안을 없애지 않는다.
- 기존 업무 작업/충돌 검토의 명시적 같은-계정 재확인은 허용한다. 같은 scope epoch를 확인한 `refresh(true,true)`는 후속 목록을 검증할 수 있지만 무효화된 보드/캐시에 다시 표시하지 않는다. 이후 범위 변경은 이 확인도 취소한다.
- 새 댓글은 범위 변경 시 저장을 잠그고 초안을 유지한다. 상세 조회의 같은 소유자 명시적 재확인 또는 기존 댓글의 동일 소유자 비교 적용은 해당 scope 잠금을 해제할 수 있다. 자체 버전·삭제/보관 제한은 유지하며 재조회/비교 적용은 저장이 아니다.

## 검증과 한계

공통 세션 단위 검사, Schedule 응답/캐시/페이지·React hook 검사 및 실제 Chrome `schedule shared read` 시나리오를 유지한다. PC/모바일·두 테마의 실패/마지막 정상값·권한 없음 화면과 가로 넘침을 확인한다. 기존 업무·댓글·버전·TODO 편집 회귀를 함께 실행한다.

`checkScheduleReads`는 대표적인 공통 연결/응답 검증 삭제와 raw bootstrap 복원을 검출하는 소스 검사다. 모든 실제 화면 쓰기가 공통 transport로 전환된 뒤 제거한 범용 `api()`와 전역 CSRF 상태도 다시 만들 수 없다. 임의 코드의 완전한 의미 검증이나 서버 인가를 대체하지 않는다. 서버에서 발급한 세션 revision을 목록마다 대조하는 새 프로토콜은 별도 작업이다. 댓글 저장은 `schedule-comment-writes.md`, 이미지 업로드는 `schedule-image-uploads.md`, 업무 상세 폴링과 업무/댓글 비교 GET의 실제 공통 연결은 `schedule-detail-reads.md`에 구분한다.
