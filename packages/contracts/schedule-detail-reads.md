# 팀 일정 업무 상세 조회

## 공통 소유자와 실제 소비자

`TaskPanel`의 초기 조회·30초 폴링·업무/댓글 변경 비교와 저장 후 조회는 `useTaskDetail`을 사용한다. 보관/복원/댓글 삭제의 `useTaskActions`도 같은 `readDetail`을 필수 전달받는다. 별도 상세 GET/폴링 기본값을 제공하지 않는다. hook은 generated `createWorkspaceReadSession`의 고정 detail 채널과 `scheduleGet` 전송, 공통 `WorkspaceState`의 로딩/오류/권한/명시적 GET 재확인을 연결한다.

## 전체 응답과 순서

- 요청 업무 ID와 반환 업무 ID, 안전한 정수 ID/버전·상태/날짜/시각/본문·편집 가능 여부를 대조한다. 보관된 업무의 canEdit=true는 거부한다.
- 댓글은 같은 업무에 속하고 ID가 고유해야 한다. 답글은 존재하는 최상위 댓글을 가리키며 삭제된 부모의 답글은 유지한다. 첨부는 같은 업무·존재하는 미삭제 댓글 또는 업무 본문에 연결되어야 한다. 이력은 ID/작성자/행동/원문/시각을 검증한다.
- 문자열 본문·이력 안의 큰 숫자/JSON을 재직렬화하지 않는다. API가 이미 안전하지 않은 정수 ID를 보내면 거부하며 이 단계에서 서버 전체 ID 전송 형식을 변경하지 않는다.
- 이미 확인한 업무/댓글 버전보다 낮은 응답과 이전 댓글 누락을 거부한다. 최신 댓글은 논리 삭제 상태로 남는 기존 서버 정책을 따른다. 이력 100개 제한·날짜/업무 정책·서버 인증/DB는 변경하지 않는다.
- 명시적인 작업의 검증된 최신 상세를 반영하면 이전 background 요청을 무효화한다. 이전 요청의 finally가 새로운 요청의 로딩 잠금을 풀지 못한다.

## 오류·계정·초안

- 처음 읽지 못한 상태를 빈 업무로 표시하지 않는다. 이후 오류에는 마지막 정상 상세와 업무·댓글 초안을 보관한다. 폴링 오류를 무시하거나 다음 폴링으로 안내를 지우지 않으며 명시적 재시도를 기다린다.
- 30초 관찰 제한은 취소를 무시하는 fetch/JSON에도 적용한다. 진행 중 읽기를 주기 타이머가 교체하지 않는다. 업무 저장/업로드·작업 전송 중에는 폴링을 보류하지만 확인창이 열려 있는 동안에는 서버 변경을 관찰한다. 비교/확인 중 기존 버전이 달라지면 기존 도메인 검증이 실행을 거부한다.
- 범위 이벤트 또는 401/403은 상세 자동 갱신과 관련 쓰기를 잠근다. 이미 읽은 내용과 초안을 복구용으로 유지하므로 삭제/익명화 기능이라고 설명하지 않는다. 명시적 재조회에서 초기 owner의 ID/역할/활성/공용/접근/관리자 scope와 회사 재확인 응답이 같아야 복구한다. 다른 계정에는 새 문서를 요구한다.
- 같은 소유자의 검증된 재조회는 상세의 읽기 잠금과 새 댓글의 scope 잠금을 풀 수 있다. 업무/댓글의 자체 버전 충돌·삭제/보관 제한은 별도로 유지한다. 이미 무효화된 뒤쪽 보드/캐시는 재노출하지 않는다.
- pagehide/라우트 해제 뒤에는 늦은 상세를 반영하지 않는다. 읽기 취소는 쓰기 롤백이나 미확정 작업 재실행 허가가 아니다.

## 검증 범위와 남은 일

React/공통 런타임 단위 검사와 실제 Chrome의 `task detail shared reads`, 기존 task confirmation/conflict review 및 일정 전체 회귀를 실행한다. PC/모바일·두 테마 화면을 직접 확인한다. `checkTaskDetailReads`는 연결/대상/관찰 삭제와 별도 전송/폴링 복원을 탐지하는 소스 검사이며 완전한 의미 분석은 아니다.

업무 생성/수정/상태의 전체 저장 ACK·미확정 잠금은 `schedule-task-writes.md`, 댓글 생성/답글/수정은 `schedule-comment-writes.md`, 이미지 업로드는 `schedule-image-uploads.md`의 별도 공통 쓰기 연결을 따른다. TaskPanel/이미지/달력 모달 프레임도 별도 계약이다. 이 읽기 단계가 모든 쓰기의 계정/늦은 응답·서버 멱등성이나 운영 SSO 검증을 완료한 것은 아니다.
