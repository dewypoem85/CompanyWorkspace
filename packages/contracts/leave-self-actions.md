# 직원 신청 취소·취소 요청 철회

목록과 월간 달력 상세는 동일 `_SelfActionForm`을 사용한다. `Cancel`과 `WithdrawCancel` native POST, CSRF, 현재 직원/중앙 세션 인가는 유지한다. `CompanyForm`이 전송/관찰, `CompanyDialog`가 실행 확인, `CompanyState`가 결과 표시를 담당한다.

## 상태와 서버 경계

| 작업 | 이전 상태 | 처리 결과 |
| --- | --- | --- |
| Cancel | Pending | Cancelled: 즉시 신청 취소 |
| Cancel | Approved | CancelRequested: 관리자 취소 승인 대기 |
| WithdrawCancel | CancelRequested | Approved: 취소 요청 철회 |

승인된 연차에 지난 사용일이 하나라도 있으면 취소 요청을 거부한다. 승인 대기 취소와 취소 철회는 기존 서비스의 정책을 유지한다. 달력에서만 이 두 동작을 지난 날짜라는 이유로 숨기던 불일치를 목록/서비스와 일치시켰다.

enhanced 요청은 `expectedEmployeeId`, `expectedSnapshot`이 필수다. 현재 로컬 직원 ID와 해당 직원이 소유한 신청을 서버에서 확인한 뒤 기준값을 대조한다. ID/기준값 누락·다른 계정/소유자·삭제/변경은 쓰기 전에 거부한다. `expectedStatus`는 화면 확인과 응답 검증용이며 서버 상태를 덮어쓰거나 인가를 대신하지 않는다. 값 없는 기존 native POST는 호환하지만 기존 소유권 검증은 유지한다.

`LeaveRequestSnapshot.Compute`는 관리자 승인과 직원 취소가 공유한다. 기존 승인 해시 정의를 그대로 추출하여 ID/직원/상태/처리 시각/사유/업무 기록/가불/배정 관련 값과 **신청 전체 날짜**를 정렬해 해시한다. 달력에 보이는 한 달의 날짜만으로 계산하지 않는다. 읽기 시점 대조이며 원자적 DB CAS, 서명된 권한 증명, 영구 멱등성이 아니다.

## 저장 응답과 UI

`workspace-form-v1` saved 응답의 `operation`, 문자열 `employeeId`/`id`, `previousSnapshot`, `previousStatus`, 결과 `status`, 로컬 `navigateTo`를 전체 검증한다. 같은 서비스의 `/Leave` 또는 `/Leave/Index` 경로와 화면의 단일 달력/목록 필터만 허용한다. 확인 중 값이 바뀌면 전송하지 않고, 응답이 캡처한 요청과 다르면 성공으로 표시하지 않는다.

처리 의도와 사용 기간·신청 사유·번호는 공통 확인창에서 구분해서 설명한다. 표시 기간/사유는 캡처한 UI 정보이고 실제 서버 기준은 전체 해시/소유권이다. 확인창 Escape는 뒤의 달력 상세까지 닫지 않으며 취소 후 원래 버튼으로 돌아간다. 목록/달력의 동적 폼 교체에도 공통 컨트롤러를 연결/해제한다. 확인/전송 중 목록·달력을 비활성화하고 배경 읽기 결과의 DOM 교체를 보류한다. 신청과 취소의 동시 실행도 같은 문서에서 막는다.

성공 후 다른 신청/관리 폼의 초안이 없으면 확인된 내역 URL로 이동한다. 초안이 있으면 유지하며 새 탭에서 최신 신청 상태/잔여량을 확인할 링크를 제공한다. 확인된 쓰기를 다시 보내서 목록을 갱신하지 않는다. `form-session.md`의 공통 세션이 처리한 신청/이전 스냅샷만 소모하므로 다른 신청이나 초안은 이어서 저장하고, 같은 신청의 관리자 강제 삭제/중복 표시 경로는 오래된 기준값으로 실행하지 않는다.

권한 오류·충돌·불완전 응답·통신/관찰 timeout·처리 도중 폼 제거는 자동 재전송하지 않는다. 확실한 사전 입력 거부만 재시도 가능하고, 나머지는 현재 문서의 추가 쓰기를 잠근 뒤 조회를 요구한다. 업무 DB 저장 뒤 감사/알림이 실패할 수 있으므로 일반 예외는 unknown으로 처리하며 내부 예외를 노출하지 않는다. 서버 rollback을 보장하지 않는다.

계정 변경·페이지 해제 뒤 늦은 응답은 무시한다. 전송 중 문서 이동에는 기존 동기 beforeunload 경고를 유지하고 확인된 성공 이동에는 표시하지 않는다. HTML 실패는 오류와 잠긴 취소 폼을 제공한다. 이 폼에는 새 업무 텍스트 입력이 없어 별도 초안 내보내기는 필요하지 않다.

## 검증 및 남은 범위

`LeaveSelfActionTests`는 실제 격리 SSO/Razor/SQLite로 상태 전환, 소유권/CSRF/기준값, 월 경계를 넘는 날짜 해시, native 호환과 commit 후 감사 실패를 검사한다. `leave-self-actions.spec.mjs`는 목록/달력 확인, 초안/정확한 응답, 동적 교체, 계정·해제·timeout 및 신청과의 경쟁을 검사한다. 구조/변이 검사는 실제 동작 검사의 대체가 아니다.

달력 강제 추가/삭제·외부 일정 편집의 개별 confirm/prompt와 별도 폼, 연차 보정/정산 UI는 아직 미전환이다. 기존 업무 DB/SSO/공개 URL을 합치거나 운영 데이터를 변경하지 않는다.
