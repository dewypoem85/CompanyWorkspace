# 통합 알림 식별자와 브라우저 계약

## 소유권

Portal의 `NotificationAggregationService`가 허용된 연차·일정 알림을 모은다. 알림 원본·소유자 인가·읽음 변경은 각 서비스에 남는다. 공통 셸과 Portal 알림센터는 같은 `CompanyNotificationContract`로 대상 키를 검증한다. 구현 원본은 `packages/workspace-ui/src/notification-contract.js`이며 생성된 공통 자산에 포함된다.

하위 서비스는 상단 종 버튼·미읽음 숫자 배지·팝오버를 별도 CSS/DOM으로 복제하지 않는다. 서비스 본문의 알림 목록·업무별 읽음 처리는 유지하되 상단 표시는 공통 셸이 단독 소유한다.

## 공개 응답과 요청

`GET /api/workspace/notifications?take=10`의 `items[].sourceId`는 **양수 64비트 정수의 십진 문자열**이다. 예: `"9007199254740993"`. 범위는 `1`부터 `9223372036854775807`까지이며 부호·공백·지수·소수점·앞자리 0을 허용하지 않는다. JavaScript `Number`, `parseInt`, 단항 `+`, 숫자 연산으로 바꾸지 않는다.

| 항목 | 표현과 처리 |
| --- | --- |
| 알림 식별자 | `{source, sourceId}` 쌍. 다른 서비스의 같은 ID는 다른 알림이다. |
| source | 현재 `leave` 또는 `schedule`. 소스 추가 시 서버 수집/인가와 공통 계약/테스트를 함께 변경한다. |
| HTML 대상 키 | `leave:9007199254740993`. `CompanyNotificationContract.key`로 전체 키를 검증한다. |
| 읽음 요청 | `POST /api/workspace/notifications/leave/9007199254740993/read`. ID 원문을 경로에 유지한다. |
| 최신 연차 ID 비교 | `CompanyNotificationContract.compare`. 문자열 길이와 십진 순서를 비교하며 숫자 변환을 하지 않는다. |
| unreadCount | 음이 아닌 안전한 정수. 식별자와 달리 실제 건수다. |

`feed`는 항목의 필드 타입·날짜 파싱 가능 여부·소스·중복 식별자와 소스 상태·건수를 검사한 뒤 새 객체로 반환한다. 기존 원본 응답을 수정하지 않는다. 잘못된 응답은 목록 렌더링과 읽음 요청에 사용하지 않는다. 링크는 별도로 셸의 회사 출처 검사에 통과해야 하며 ID 검사가 링크 안전성을 대신하지 않는다.

## 요청 수명주기와 계정 범위

`CompanyNotificationSession`이 공통 셸의 조회와 셸/Portal 알림센터의 읽음 요청을 직렬화한다. 현재 사용자 ID·역할·관리자 여부·허용 서비스 목록을 범위로 캡처하며, 범위 변경/화면 해제 후 늦은 fetch 또는 JSON 응답은 반영하지 않는다. 응답 관찰은 15초로 제한하며 브라우저 취소가 서버 취소나 롤백을 의미하지 않는다.

- 새 클라이언트는 GET과 개별/전체 읽음 POST에 `expectedUserId=<요청 당시 회사 사용자 ID>` 쿼리를 보낸다. Portal은 현재 인증 사용자와 정확히 대조한다. 빈 값·중복·불일치는 내부 알림 API 호출 전에 409로 거부한다. 배포 호환을 위해 **쿼리가 없는 기존 요청은 유지**하므로 이 추가 보호는 새 클라이언트 경로에 적용된다.
- 쓰기 완료는 정확한 HTTP 204로 확인한다. HTML/다른 성공 코드/통신 실패/timeout은 반영 여부 미확정이며 쓰기를 자동 재전송하지 않는다. 미확정 시 쓰기를 잠그고 목록 재확인(GET)만 제공한다.
- 읽음 완료 후 목록 갱신에 실패해도 확인된 읽음 성공을 취소하지 않는다. 성공과 조회 실패를 구분하고 재확인은 GET만 수행한다. 알림 상세 이동과 본문 읽음 후 native 재로딩도 완료 확인 뒤에만 실행한다.
- `CompanyState`가 공통 셸의 조회·빈 결과·부분 장애·저장 결과 및 본문 쓰기 결과를 표시한다. 일시적 조회 실패/손상 응답에는 이전의 검증된 목록을 유지하되 쓰기를 잠근다. 401/403/409와 계정 범위 변경은 이전 목록·미읽음 배지·브라우저 알림을 지운다. 부분 소스 장애는 확인된 목록과 경고를 함께 표시한다.
- Portal 본문은 서버에서 렌더링한 계정 ID를 보유한다. 해당 문서의 계정/권한 범위가 무효화되면 이전 본문을 지우고 현재 알림 페이지를 다시 열도록 한다. 팝업의 새 계정 조회 성공만으로 이전 본문 전체 읽음 버튼을 다시 허용하지 않는다.

## 호환성과 한계

- Portal 내부 모델과 읽음 route/service 인수는 `long`을 유지한다. `SourceId` 속성에만 JSON 문자열 직렬화를 적용하므로 전체 API 숫자 직렬화 설정이나 DB를 바꾸지 않는다. 기존 내부 소스의 숫자/문자열 응답은 .NET에서 모두 정확히 읽는다.
- 브라우저는 배포 전환 중 안전한 정수 범위의 구형 숫자 응답만 문자열로 정규화한다. 안전 범위 밖의 JSON 숫자는 원래 ID를 복구할 수 없으므로 거부한다. 새 클라이언트는 처음부터 문자열 응답을 사용해야 한다.
- CSRF, 현재 회사 계정, 서비스 접근 권한, 내부 HMAC 및 원본 서비스의 알림 소유자 검증은 별도 적용한다. 형식에 맞는 ID라는 이유만으로 읽음을 허용하지 않는다.
- 이 계약은 읽음 요청의 영구 멱등성·계정/권한 변경과 서버 쓰기 사이의 원자적 경쟁 제어·모든 업무 상태 UI 전환을 보장하지 않는다. Portal 본문의 최초 서버 렌더링은 native 조회 화면으로 유지한다. 프로필 설정 폼과 다른 업무 UI의 공통화, 운영 인증·배포 검증은 별도 이관 대상이다.
