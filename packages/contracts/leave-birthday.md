# 직원 생일·생일연차 계약

## 원본과 공개 범위

- 생일 원본은 Portal `CompanyUser.BirthDate`이며 선택 입력이다. 관리자 직원 등록·편집 화면은 출생 연도를 받지 않고 `MM-DD` 월·일만 읽고 쓴다. DB의 `DateOnly`에는 윤일을 표현할 수 있는 기준연도 2000을 내부적으로 사용하며 응답은 연도를 개인정보로 해석하거나 노출하지 않는다.
- 생일은 일반 직원/프로젝트 디렉터리, 프로필, 일정, 통계, CS, Sheet, IAP 응답이나 토큰에 노출하지 않는다. Leave 로그인·provision 토큰에만 서명된 `birthDate`를 포함하고 Leave의 `Employee.BirthDate`는 아래 달력 표시용 투영본이다.
- Leave 전용 새 토큰의 `birthDate`는 `MM-DD`이고 명시적 `null`은 기존 생일을 삭제한다. 배포 순서 중 구버전 `yyyy-MM-dd` 토큰은 월·일만 정규화해 수용하고, claim 자체가 없으면 Leave의 기존 값을 보존한다.

## 달력 표시

- 일반 직원은 월간·연간 연차 달력에서 본인 생일만 볼 수 있다. `다른 사람 연차도 같이 보기`를 켜도 다른 직원 생일은 노출하지 않는다.
- 관리자와 마스터는 전체 보기에서 활성 실제 직원의 생일을 볼 수 있다. 비공개 직원도 관리자에게는 표시하지만 공용 계정·회사 마스터·퇴사 직원은 전체 목록에서 제외한다. 관리자 본인은 회사 마스터 여부와 무관하게 표시한다.
- 관리자 `자기것만 보기`와 대신보기에서는 현재 선택 직원의 생일만 표시한다. 2월 29일생은 평년 달력에서 2월 28일에 표시한다.
- 생일 칩과 날짜 상세는 앞에 장식용 케이크 아이콘을 붙이고 이름·로컬 직원 ID만 렌더링하며 출생 연도나 저장 기준연도 2000은 노출하지 않는다. 색은 공통 violet 의미 토큰을 사용해 라이트·다크 테마를 함께 지원한다.

## 생일연차 신청

- `LeaveDayPortion.Birthday=5`는 정규 신청 유형이다. 기존 enum 값 0~4는 변경하지 않는다.
- 직원은 해당 연도의 생일 당일 기준 전후 30일을 포함한 기간 안의 미래 근무일 하루만 신청한다. 반차·다일 신청은 허용하지 않는다.
- 기준 생일이 입사일보다 이르고 현재 활성 직원인 경우만 대상이다. 퇴사 예정일 정보는 없으므로 미래 퇴사를 소급 반영하지 않는다.
- 신청은 기존 승인·반려·취소 흐름을 사용하며 `CalculatedDays=0`, `IsAdvance=false`, `IsBirthdayLeave=true`다. 일반 연차·월차·가불·배정·정산에 영향을 주지 않는다.
- `BirthdayBenefitDate`는 신청이 속한 실제 기준 생일을 저장한다. 같은 기준 생일의 Pending/Approved/CancelRequested는 하나만 허용하고 Rejected/Cancelled 후에는 다시 신청할 수 있다.
- 생일연차 유형을 볼 수 있는 범위는 본인·관리자다. 다른 일반 직원의 달력과 Schedule 부재 API, 공용 Discord 채널에서는 일반 `연차`/`full`로 표시한다.

## 사용 가능 안내·관리자 예외

- 연차 대시보드는 오늘이 생일 전후 30일 안이고 혜택이 미사용이면 상단에 사용 가능 기간·미차감·1일을 표시하고 신청 폼으로 이동하는 버튼을 제공한다.
- 신청 폼은 생일연차 선택 시 종료일을 시작일로 고정하고 선택 날짜의 기간·재직·기사용 여부를 즉시 안내한다. 클라이언트 안내는 보조 수단이며 서버가 최종 검증한다.
- 관리자 강제 추가는 생일 정보가 있는 활성 실제 직원에게만 할 수 있다. 사유를 남기면 기간·재직·연 1회 제한을 예외 처리하고 `IsBirthdayPolicyOverride=true`로 감사한다. 기간 밖 기록은 선택일과 가장 가까운 생일에 귀속한다.

## 소멸과 과거 기록

- 미사용 혜택은 기간 종료 후 소멸하며 일반 연차로 전환·이월·지급하지 않는다. `Birthday` 자동 지급은 중단 상태를 유지한다.
- 이미 저장된 `LeaveRequestDate.IsBirthdayLeave=true` 신청은 같은 기준 생일의 기사용 혜택으로 인정한다. 기존 `Birthday` 지급분·`BenefitYear`는 삭제·재생성·재계산하지 않고 과거 정산 호환을 위한 역사 값으로만 읽는다.

이 계약은 비공개 인사 입력과 Leave 달력의 제한된 생일 표시를 연결한다.
