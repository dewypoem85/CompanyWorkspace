# 같은 서비스의 본문 전환

공통 페이지 라우터는 중앙 페이지 목록에서 `clientNavigation: true`로 지정한 같은 출처의 메뉴 GET 링크만 다룬다. 응답은 기존 서버의 인증·권한 검사를 거친 HTML이며, `CompanyReadSession`의 단일 채널에서 취소·제한 시간을 관찰한다. 응답이 리디렉션되거나 HTML이 아니거나 서비스·페이지 ID·사용자 식별자·역할이 현재 문서와 다르면 본문을 교체하지 않고 일반 문서 이동으로 복구한다. CS의 정적 HTML은 인증 게이트웨이가 부여한 `X-Workspace-Identity` 응답 헤더를 현재 회사 계정과 비교한다. HTML이나 업무 데이터를 브라우저 저장소에 캐시하지 않는다.

본문 교체 전 페이지별 `beforeLeave` 확인과 `dispose`를 완료한다. Portal·Leave는 서버 렌더링 페이지의 명시적인 `[data-workspace-page-scripts]` 영역만 순서대로 초기화한다. Leave 모듈은 재방문 시 `mountWorkspacePage`를 호출하며, 기존 페이지의 폼 세션·읽기·관찰자는 `company-page-leave`에서 정리한다. CS는 페이지 ID별로 허용된 모듈만 시작·정리하며 페이지 전용 스타일도 함께 교체한다. 이 계약이 없는 페이지에는 `clientNavigation`을 부여하지 않는다. 인증·로그아웃·서비스 간 이동, 다운로드, POST 및 일반 GET 폼 제출은 기존 문서 이동을 유지한다. 예외로 Leave 대시보드의 관리자 `대신보기` GET은 직원별 잔액·내역·쓰기 권한을 함께 바꾸기 위해 같은 페이지의 본문 라우터를 호출한다. 초안 폐기 확인을 거치고 서버 응답 검증에 실패하면 전체 GET으로 복구한다. 뒤로/앞으로 이동과 URL·메뉴·제목·포커스·스크롤을 함께 갱신한다.
