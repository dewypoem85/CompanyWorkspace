# 팀 일정 목표·상세 일정·공용 TODO 계약

## 소유권과 표시 범위

- Schedule DB가 `WorkGoals`, `TaskScheduleItems`, `SharedTaskTodos`와 `Tasks.GoalId`를 소유한다. 기존 업무·댓글·개인 TODO와 별도 테이블이며 추가형 스키마 변경만 수행한다.
- 업무 목표는 접근 가능한 직원이 생성·종료·재개할 수 있다. 프로젝트 목표는 해당 프로젝트가 보이는 계정만 사용하며 종료 후에도 기존 업무 연결은 보존한다.
- 상세 일정은 업무 편집 권한이 있는 직원만 등록·수정·삭제한다. 일반 직원별·프로젝트별·부서별 보드에는 포함하지 않고 업무 상세와 `내 일정`에서만 표시한다.
- 공용 TODO는 업무를 볼 수 있는 직원이면 등록·완료/완료 취소할 수 있다. 내용 수정·삭제는 등록자 또는 회사 관리자만 가능하다. 등록자, 완료자, 완료 시각을 서버가 기록한다.

## 조회·쓰기 경계

- 업무 상세 GET은 `scheduleItems`, `sharedTodos`를 함께 반환한다. 보드 GET은 `includePlanning=true`일 때만 두 목록을 반환하여 일반 보드의 전송량을 늘리지 않는다.
- 목표는 bootstrap의 `goals`로 제공하며 비공개 프로젝트 필터를 그대로 적용한다.
- 새 쓰기 API는 공통 `workspace-form-v1` transport, `X-Workspace-Actor`, CSRF, 행 `Version`을 사용한다. 미확정 응답은 자동 반복하지 않으며 성공 뒤 목록/상세만 다시 읽는다.
- 목표·상세 일정·공용 TODO 쓰기 훅은 `schedule-planning-writes` 문서 세션에 각 화면 소유자를 먼저 등록한 뒤 lease를 시작하고, 화면 해제 시 소유자를 제거한다. 등록되지 않은 소유자로 `begin()`을 호출해 정상 쓰기를 전송 전에 차단하면 안 된다.
- 모든 변경은 기존 `ChangeLog`에 작업자와 대상 내용을 남긴다. 업무 삭제/보관, 프로젝트·계정 접근 정책은 기존 Schedule 인가를 우회하지 않는다.

## 화면 계약

- 상단 보기 전환은 주간·월간·칸반을 제공한다. 분류는 직원별·프로젝트별·부서별·내 일정 순서이며 별도 `내 일정` 필터 버튼을 만들지 않는다.
- 월간 달력은 6주(42일)를 한 번에 읽고 주말·공휴일·오늘을 의미 토큰으로 구분한다. `내 일정`에서는 본문, 목표, 상세 일정까지 표시한다.
- 프로젝트/부서 주간 보드는 그룹 접기/펼치기는 유지하되 개별 업무명을 반복하는 고정 왼쪽 열을 렌더링하지 않는다.
- 기간 업무의 카드 본문은 가로 스크롤 중 화면 안에 붙어 이동하되 카드의 시작·끝 범위를 벗어나지 않는다.

## 검증

- `WorkPlanningTests`는 목표 생성·연결·종료, 상세 일정 권한, 공용 TODO 등록·완료·감사 기록, 보드 포함 조회를 실제 TestServer와 SQLite로 검증한다.
- `usePlanningWrites.test.ts`와 실제 Chrome 업무 상세 시나리오는 공용 TODO·상세 일정이 등록된 문서 세션에서 차례로 전송되고 저장 후 상세에 반영되는지 검사한다. Schedule Vitest와 TypeScript/Vite 빌드는 기존 업무·댓글·읽기/쓰기 계약의 호환성을 검증한다. 운영 SSO와 배포 성공은 배포 전 점검과 서비스 상태 확인으로 별도 검증한다.
