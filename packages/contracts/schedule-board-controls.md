# 팀 일정 탐색·필터 컨트롤

주간 일정/칸반의 분류·업무 등록·이전/다음/오늘·날짜 이동·표시 기간·내 일정과 부서/프로젝트/직원 필터는 공통 native 필드/버튼을 사용한다. 날짜 미정·주말 안내·더 보기와 칸반 상태 select도 같은 primitive를 소비한다. 직원/프로젝트 검색은 기존 공통 entity 선택기와 실제 option ID를 유지한다. 일반 필터 라벨은 화면에도 표시한다.

## 소유권과 상태

- 필드/버튼의 색·크기·hover·선택·비활성은 공통 소유다. 직원/프로젝트/부서 분류, 내 일정과 날짜 미정 버튼은 실제 값에 연결한 aria-pressed를 사용한다. 주말 표시·선택한 주만과 상세 보기 입력은 `cw-check-control`/`cw-checkbox`이며 공통 18px 크기와 선택·hover·focus·disabled 테마를 사용한다.
- 보기 설정은 generated useWorkspaceDisclosure를 사용한다. 공통 컨트롤러가 hidden/ARIA/포커스를 소유하며 React는 본문과 업무 값만 유지한다. 펼침 알림은 문구와 페이지 왕복 시 선호 상태 복원에만 사용한다.
- 날짜 미정/칸반에서는 외부 slot을 숨기고 내부 필드를 없애거나 값/펼침 상태를 다시 쓰지 않는다. 개인 TODO 등 다른 본문으로 이동했다 돌아오면 공통 API로 이전 펼침 상태를 복원한다. 중첩 공통 disclosure 루트는 각각의 소유자를 유지한다.
- 기존 grouping/visibleWeeks/rowHeight 저장 키, 필터 query·기간 확장/캐시·담당자 ID·URL 및 권한 검증을 유지한다. 접기는 접근 통제가 아니다.
- boardControls.css는 분류/필터/날짜 범위의 배치만 담당한다. 모바일 필터는 전체 폭이며 날짜 범위를 잘라 숨기지 않는다. 예전 detail.css의 46% select 제한과 overview의 중복 버튼 스타일을 다시 추가하지 않는다.

## 보드 작업과 색상 안내

WeekBoard의 업무 모두 펼치기/접기·집중 보기·이전/다음 기간 읽기·주요 일정 밀도·직원/프로젝트/부서 행 펼침·모바일 날짜별 업무 등록은 공통 버튼을 사용한다. 밀집 보드 작업은 compact 32px, 모바일 등록은 이름 있는 compact/icon 버튼이다. 로딩 중 기간 버튼은 실제 disabled, 집중 보기는 실제 aria-pressed, 행 펼침은 실제 aria-expanded를 유지한다. 스타일을 위해 가짜 선택 상태를 붙이지 않는다.

색상 안내는 generated useWorkspaceDisclosure의 독립 보드 루트에 연결한다. 상위 App의 보기 설정과 소유권을 섞지 않으며 모바일에서도 열 수 있다. 범례 본문은 그대로 보존하고 컨트롤러가 hidden/ARIA를 관리한다. 이 안내는 비모달 disclosure이며 별도 모달·팝오버 수명주기를 복제하지 않는다.

## 예시 데이터와 오늘 상태

예시 데이터는 warning, 오늘 문구는 info `cw-state-pill`을 사용한다. 공통 primitive가 글자·배경·간격·모서리와 두 테마를 소유하며 일정 CSS는 별도 palette나 크기를 만들지 않는다. 모바일에서는 예시 데이터 표시를 숨기고, 데스크톱 밀집 보드에서는 오늘 문구 대신 기존 열 테두리를 사용한다. 이 두 표시 정책은 상태 의미나 색상 소유권을 바꾸지 않는다.

`schedule demo and today indicators use shared semantic pills` 브라우저 시나리오는 고정된 오늘 날짜와 demo 응답으로 320/1440px·라이트/다크의 class/tone, 계산 색, 기존 숨김 정책과 문서 폭을 확인한다. 이 검사는 운영 demo 설정이나 공휴일 공급 성공을 증명하지 않는다.

업무 행 전개는 단순 DOM hidden이 아니다. visibleLanes·allExpanded/직원별 반전 집합이 카드 수와 grid lane을 계산하고 모바일 같은 직원의 여러 날짜에도 적용한다. 이 도메인 계산을 일반 disclosure로 바꾸지 않는다. 버튼 색/높이만 공통 소유로 이관하며 부서 표식과 겹침 배치는 보존한다. 접기 버튼은 이름/부서 아래에 배치해 32px 컨트롤이 기존 절대 위치에서 겹치지 않도록 한다.

week board actions preserve 시나리오는 4개 겹친 업무의 개별/전체 펼침, 그룹 행 접기, 주요 일정 요약 밀도, 집중 보기 왕복, 기간 추가 GET과 지연 중 비활성, 모바일 직원/날짜별 신규 편집 진입을 검사한다. PC/모바일·두 테마의 계산 색·크기와 실제 viewport를 확인한다. 업무/주요 일정 카드와 셀 전체 등록 overlay는 아래의 record cards and cell 시나리오에서 별도로 검증한다.

## 필터 검증

schedule-shell.spec.mjs의 board filters share 시나리오는 320/1440px × 라이트/다크에서 실제 번들/공통 자산을 사용한다. 계산 색·44px·라벨, 선택 상태, 초성 프로젝트 선택/포커스, 실제 GET query, 기간/분류 선호를 검사한다. checkbox는 공통 class·18px 크기·선택 배경을 확인하고 상세 보기 switch 의미, 공통 range의 행 높이·출력·선호 저장, 접기 후 DOM 유지, 날짜 미정/칸반/TODO 왕복을 함께 보존한다.

필터 입력 폭과 날짜 범위 글자의 내부 넘침도 검사하며 board-controls.png와 kanban-controls.png를 직접 확인한다. 본문 없는 칸반 toolbar처럼 필드가 원래 없는 루트만 테스트에서 최소 필드 수를 0으로 명시하며 존재하는 필드의 검증은 생략하지 않는다.

## 업무·주요 일정 카드와 셀 등록

App의 업무 카드는 공통 record/content 버튼에 프로젝트 색을 --record-accent로 전달한다. WeekBoard는 시작일~종료일의 단일 날짜 구간을 실선 카드로 표시하고 드래그 ID·기존 상세 경로를 유지한다. 주요 일정도 같은 record를 사용하며 유형별 식별 색만 앱이 매핑한다. 버튼 본체의 배경·글자·hover·비활성 복제 CSS는 제거한다.

PC 날짜 셀의 전체 등록 영역은 quiet/overlay 공통 버튼이며 작은 버튼으로 동작 영역을 줄이지 않는다. 모바일은 기존 명시적 icon 등록 버튼이다. record cards and cell 테스트는 모든 실제 카드/셀 계산 색과 최소 크기, 실선 테두리, disabled/선택 우선순위, 상세 키보드 진입, 정확한 직원/날짜 등록, 칸반 dragstart의 task ID를 검증한다. 합성 dragstart 검사는 서버 상태 PATCH 성공이나 실제 DB 변경을 의미하지 않는다.

## 월간 업무 리본

월간 달력은 업무를 날짜마다 복제하지 않고 시작일~종료일을 주 단위의 한 리본으로 배치한다. 주 경계를 넘는 업무는 다음 주에도 같은 레인을 우선 사용하고, 시작·종료 모서리로 앞뒤 기간의 연속 여부를 구분한다. 겹치는 업무만 다음 레인을 사용하며 빈 주의 높이는 불필요하게 늘리지 않는다.

리본은 공통 record/content 버튼과 프로젝트 `--record-accent`를 사용한다. 프로젝트 아이콘·업무명·담당자 프로필과 이름·상태를 항상 포함하고, 내 일정에서는 기존 본문 요약을 한 줄 더 표시한다. 좁은 화면은 달력 자체의 가로 스크롤을 유지하되 담당자 이름을 숨기지 않는다. 날짜 셀의 주말·공휴일·오늘 상태, 주요 일정, 날짜별 등록 버튼과 기존 상세 열기 경로도 유지한다.

monthly calendar and detailed my schedule 시나리오는 PC 라이트와 모바일 다크에서 42개 날짜, 공휴일, 기간 5일 업무가 한 리본으로만 렌더링되는지 확인한다. 리본 폭이 날짜 한 칸보다 실제로 넓은지, 담당자와 내 일정 본문이 보이는지, 문서 가로 넘침 없이 달력 내부 스크롤로 탐색하는지도 검사한다. 이 합성 브라우저 검사는 운영 일정 데이터나 서버 쓰기를 변경하지 않는다.

## 남은 동작 경계

보드 상단 checkbox/switch와 직원 행 높이 range의 시각·상태는 공통 primitive가 소유하지만 값 범위·선호 저장과 행 배치/집중 보기 계산은 앱에 남는다. 개인 TODO 완료 checkbox와 각종 표식은 별도 도메인 컨트롤로 후속 검토한다. 초기 정보/보드 읽기 오류·부재 경고는 `schedule-reads.md`의 공통 조회/상태로 전환했다. 상태 PATCH와 업무 저장은 `schedule-task-writes.md`, 댓글 저장은 `schedule-comment-writes.md`, 이미지 업로드는 `schedule-image-uploads.md`로 전환했으며 주요 일정 저장 등 남은 수명주기는 별도 전환 대상이다. 기존 서버 API·DB·인가를 바꾸지 않았으며 합성 읽기 테스트는 서버 쓰기의 전체 ACK·경쟁 제어·롤백 증거가 아니다.
