# 공통 사이드바 권한 조회

서버 권한이 필요한 Razor 서비스의 사이드바는 `navigation.js`가 `/api/workspace/navigation`을 읽은 뒤에만 페이지를 표시한다. 클라이언트의 역할 추측이나 이전 계정의 캐시만으로 링크를 노출하지 않는다.

- 서비스별 고정 `workspace-navigation-*` 채널을 `CompanyReadSession`으로 관찰한다. 같은 서비스의 재시도·포커스 갱신은 이전 요청을 취소하고, 서로 다른 서비스 채널은 독립적이다.
- 회사 계정·역할·허용 서비스 범위가 바뀌거나 로그아웃하면 모든 진행 중 권한 조회를 먼저 취소하고 기존 페이지·badge·상태를 제거한다. 문서가 실제로 해제될 때 read session도 dispose한다.
- 요청은 same-origin 자격 증명, no-store, JSON Accept와 redirect 오류 정책을 유지한다. 응답 본문을 모두 읽은 뒤 AbortSignal과 최신 ticket을 다시 확인하고 나서만 화면에 적용한다.
- 권한 조회를 시작할 때 badge별 로컬 갱신 revision을 기록한다. 조회가 진행되는 동안 승인 대기열 등 화면이 `setBadge`로 더 최신 값을 적용했다면 늦게 도착한 권한 스냅샷은 그 badge를 덮지 않는다. 최신 로컬 갱신 이후에 명시적으로 시작한 새 권한 조회는 서버 값을 적용할 수 있다.
- `pages`는 해당 서비스에 등록된 탐색 페이지 문자열만 허용한다. `badges`가 객체가 아니면 전체 응답을 거부하며, badge가 등록되지 않았거나 현재 허용 페이지 밖인 항목과 음수·소수·문자열 count는 표시하지 않는다.
- 401은 로그인 확인, 403은 권한 거부, 그 밖의 HTTP·JSON·스키마·8초 관찰 제한 오류는 재시도 가능한 실패로 구분한다. 취소된 이전 요청은 현재 상태를 성공이나 오류로 덮지 않는다.

이 계약은 메뉴 조회 관찰만 다룬다. 서버 인가, 서비스 본문 조회, 저장, SSO 세션 갱신을 대신하지 않는다.
